# 钱包渠道授权需求与施工单

本文件是本轮签名渠道施工的当前约定，优先于历史文档中“主机修改硬件额度”“Peer Record 默认手工或使用 USB 会话持续决定”等描述。

## 需求边界

身份首先是固定的 `(bsvNetwork, publicKeyHex)`；main/test 是两个身份和存储根，不通过临时 testnet 开关修改当前私钥所属网络。本轮在 c9a87e4 的网络身份施工上继续，不恢复旧语义。

所有业务签名须先登记渠道。支付继续使用已有渠道、实际交易解析及额度账本；非支付签名使用注册渠道的 automatic/manual 模式，不能拿非支付渠道签交易，也不能拿另一操作的渠道编号签名。迁移、PIN 和 USB 实体配对保持原有独立安全门禁。

初次注册提交来源和建议；钱包用户确认后保存。Noise 与 Peer Record 是两个独立渠道，建议自动；其他已支持的非支付签名建议人工。建议不是后续设置命令，重复注册不覆盖用户选择。软件 Vault 内部设置软件策略，RocKey 本机设置硬件策略；Keymaster 展示硬件设置，不提供修改硬件授权模式或额度的入口。

支付策略仍为每笔最大免确认金额；外部 App 一次 Connect 连接使用跨支付渠道的累计总额。超单笔、超累计或关闭免确认均允许用户批准本次；确认中可提高当前会话总额。一次批准不重置用量，不默认提高未来额度。已经签署、未知或已归档的使用记录保留。App 重新注册、串口重连及刷新不得清空预算。

信用信息不实施，不恢复统一软硬钱包业务确认弹窗。软件自动模式不弹窗；软件人工模式及超额支付由 Vault 自有弹窗确认。硬件自动模式没有授权页，使用独立自动提示音；人工模式在设备上阅读、授权或否决。

## 实现

- VLP 策略 bank v4 把网络和签名渠道纳入原账本；迁移携带同一份 bank，保留支付、会话、归档及签名设置。原有 v2/v3 记录按保留数据的升级路径读取。
- SoftwarePaymentGate / WalletPayments 实现软件注册、策略编辑、等待确认和签名前修订检查。确认期间改动该渠道，旧确认失效。
- HardwareBackend 在受限签名 Profile 外包 `signing.execute`，携带渠道编号及原完整正文和承诺；注册建议由设备确认，Keymaster 不传“已同意”。
- Vault 渠道设置显示签名模式和支付额度。硬件设置只读；软件模式修改由 Vault 内部控制面提交。待确认、批准和否决独立于正在等待的签名队列。
- 软件原始摘要、Channel 消息、Window P2P 身份签名及已有支付路径进入钱包策略。硬件仍只支持原先已实现的语义 Profile，无通用摘要盲签。
- Coding/keymaster/p2p-host 先为当前 Host 生成 X25519 静态公钥并取得 Noise 证明，之后才构造 libp2p Host。只缓存这一静态公钥的证明，Host 关闭清理；Peer Record 使用自身完整记录先签再 push。适配器及涉及人工等待的 RPC 保留钱包等待时间，不由原 5 秒签名计时或普通 30 秒 RPC 提前清掉授权页。
