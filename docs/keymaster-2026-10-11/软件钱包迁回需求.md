# 钱包迁移：一次提交，设备授权

## 已确认的需求

1. Keymaster 网页收集并确认新的软件钱包密码，检查原 RocKey 连接。
2. 网页发起迁回请求。已解锁的 RocKey 展示私钥进入软件环境的警告，由用户长按确认；不重复输入 PIN。
3. Coordinator Worker 接收私钥，验证身份，创建并验证新密码加密的钱包，将钱包、消费账本、迁移完成记录原子保存。
4. 保存成功即完成迁回，自动建立软件钱包会话、进入正常首页，不要求再次输入密码，不等待设备擦除。
5. 同时向原 RocKey 发送独立擦除请求。设备允许长按同意擦除，也允许否决保留备份。否决、未响应、断线均不影响软件钱包完成状态。
6. 删除 RocKey 原有迁回菜单、预先开启导出流程和相关过时入口。

## 完成边界和异常

- 软件迁回完成以浏览器加密钱包和账本事务提交成功为准。设备副本的处理是独立动作，不能成为首页或后续解锁的门禁。
- 浏览器只保存最终完成记录；准备数据只存在于本次 Worker 内存，不持久化迁移中状态。提交前失败或刷新保留原钱包，提交后正常使用目标钱包。完成记录仅含公开身份与哈希，不保存私钥或密码。
- 保存前失败应展示具体原因；保存后软件会话装配失败应允许用新密码解锁，不能误报仍需设备迁移。
- USB 连接在软件会话接管后临时保留，仅用于同一迁移的公开提交通知和设备擦除决定。锁定、重置、身份变化仍须撤销连接。
- 设备擦除必须绑定原身份、迁移 ID 与已提交钱包的哈希，禁止过期请求擦除另一把私钥。
- 保留备份时，软件和设备消费账本不是实时同步账本。
- 迁入仅允许空 RocKey。网页已解锁时不再输入软件密码；取得实际设备保存和完成证明后，原子替换浏览器钱包、账本与完成记录。已有任何私钥都拒绝迁入。

## 验收

- 无设备菜单操作即可由网页触发导出，设备只需长按授权。
- 浏览器保存后软件会话保持解锁，首页可使用；设备确认停留不阻塞软件业务。
- 设备同意、否决、未响应、断线四种情况均不撤销软件会话或制造未完成迁移。
- 私钥、密码只在 Worker 内使用，临时字节清零；设备擦除前浏览器记录必须已经提交。
- 重启后完成的软件钱包可以用新密码解锁；未提交操作保留原钱包，旧版遗留标记严格验证后清除。
- RocKey 菜单不再显示旧迁回入口；删除入口后菜单索引和其它功能保持正确。

## 实施范围

Keymaster 迁移服务、Coordinator 会话接管和 USB 连接生命周期、迁回与恢复页面；RocKey 请求授权、可选擦除和旧菜单删除；共享协议的迁移完成语义及对应真实密码/存储/设备互通验证。

## 实施记录

- 两个方向的浏览器准备过程仅在内存中进行，最终事务直接提交 `complete`；迁入前必须取得真实设备保存证明。
- 使用本次新密码在 Worker 内接管软件会话。USB 单独转为迁移清理连接，不继承软件钱包权限，设备决定结束或连接失效后关闭。
- 软件业务运行绑定在迁移锁释放、存储根安装后恢复，避免嵌套 I/O 被自己的迁移锁拒绝。
- RocKey 的网页请求改为已解锁状态下的实体长按授权；删除旧菜单及导出预先武装接口，同步调整菜单索引与导航测试。
- 保存前失败保留原会话并在当前弹窗显示具体错误；完成记录不会因擦除未决定而变回未完成。
- 验证使用真实 Coordinator、IndexedDB、KeyHold 密码学及 RocKey C++ 协议/KeyStore。HOST 串口和按钮事件适配不代表实体 USB、实体按键或 Flash 掉电验收。

## 迁移提交规则修订（用户确认）

- 浏览器只保存最终完成记录。准备数据、校验密码、设备授权和保存证明均属于本次内存操作，不持久化“迁移中”，不因未完成操作锁死钱包。
- 最终提交前取消、断线、失败或刷新，保留原钱包和原业务数据；提交时原子替换后端、账本和完成记录。
- RocKey 已有任何私钥都禁止迁入，包括相同私钥。连接时提前检查，设备导入时再次拒绝；不提供同私钥接管或覆盖。
- 若设备已保存而浏览器尚未提交就中断，浏览器保持软件钱包，设备保留已保存的私钥；再次迁入按“已有私钥”拒绝，不自动擦除。
- 对旧版遗留记录，只有严格验证源钱包仍完整、身份和世代一致后，才能删除未提交标记并恢复正常启动；已提交的目标钱包不能回退成源钱包。

- 迁入只从当前已解锁的 Worker 会话取得私钥副本，不再要求软件钱包密码；会话失效就中止，副本在成功、失败与撤权后均清零。页面和 RPC 不传密码或私钥。设备实体授权及 PIN 设置仍保留。
