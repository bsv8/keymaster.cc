# 存储

Keymaster 把“桶”作为最外层数据边界。一个桶可以包含多把 Key、系统配置和各 Owner 的
业务数据。当前实现支持 Local（浏览器 `localStorage`）和 S3 两类 Provider，不使用 OPFS。

## 数据放在哪里

| 数据 | 位置 | 说明 |
| --- | --- | --- |
| 桶目录 | 浏览器公共存储 | 桶名称、后端、加密连接记录和当前选择；不含 Key 列表 |
| 私钥密文 | 当前桶 `.keymaster/hold/v1` | Hold 快照是私钥密文唯一真相 |
| 桶级配置 | 当前桶系统命名空间 | Coordinator、Storage、Protocol、Vault 的受限数据 |
| Owner 数据 | `<publicKeyHex>/.keymaster/modules/...` | 联系人、消息、资产、文件设置等按模块和用途隔离 |
| 运行状态 | 内存 | 密码、解密凭据、私钥、连接、锁、计时器和在途请求 |

`publicKeyHex` 表示 66 位压缩公钥十六进制字符串，是平台身份主键。

## 桶与密码

- Local 桶把对象写入受控的 `localStorage`；业务插件不能直接访问浏览器存储。
- S3 页面提供 AWS S3、Cloudflare R2 和普通 S3-compatible 三种填写方式，最终转换为
  同一个 S3 连接结构。
- 桶密码同时保护连接配置和 Hold，但只在测试、解锁、切换、导出或改密期间存在内存。
- 同桶切换 Key 也要重新输入桶密码；Keymaster 不长期保存桶密码。
- S3 必须支持原生条件写入，不能用“先读后写”冒充原子更新。

## 中央存储

内置模块必须在中央注册表声明以下字段：

| 字段 | 中文含义 |
| --- | --- |
| `moduleId` | 模块稳定编号 |
| `purposeId` | 本份数据的用途编号 |
| `scope` | 桶级或 Owner 级归属 |
| `authority` | 平台专用或内置模块权限 |
| `model` | 固定快照或 K-V 模型 |
| `schemaVersion` | 数据结构版本 |

固定配置使用 CAS Snapshot（带版本比较的完整快照）；普通数据使用 full-head K-V：先写唯一
value，再以 CAS 发布包含全部键引用的新 head。写入不产生永久 commit 历史，垃圾回收异步
清理不再被当前或旧读者引用的 value。

插件拿到的是 Borrowed Store（借用存储句柄）。句柄由 Coordinator 打开和关闭；插件关闭
自己的 Repository 不得关闭共享底层。切桶、锁定或 Owner 变化会使旧句柄立即失效。

## 首次初始化

页面在最终确认前只保存内存草稿。用户确认后一次提交完整计划：

```text
验证桶和条件写入
→ 暂存中央句柄、Hold 与第一把 Key
→ 提交桶对象和本机目录选择
→ 安装 Coordinator 运行态
```

任一步失败都必须清理暂存资源。若远端结果无法确认，则保留脱敏恢复记录，不能把半成品
当成成功，也不能盲目重复写入。

## Connect App 存储

外部 App 只有在会话绑定了有效身份并声明 `storage` 需求时才能使用 `storage.*`。命名空间
由 Owner、发行人公钥和 App ID 派生；App 只能提交相对路径，不能指定桶、Provider、凭据、
Owner 或物理前缀。单次对象上限与 multipart 分片上限以契约常量为准。
