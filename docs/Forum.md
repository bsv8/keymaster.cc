# Forum

Forum 是 BSV8 Forum 的客户端。论坛服务器提供节点索引、分页与报价；帖子正文和附件通过 MSFile 获取、验证和统一保存，由 Forum 解析展示。

## 运行与信任

Window 提供论坛配置、列表、正文和发布页面，并把 Forum lane 注册到现有唯一 Window P2P Host。owner-session Worker 独占配置、缓存和任务仓储、业务签名、报价复核、最终 raw 校验及提交仲裁。页面仅调用结构化 RPC，附件走分块 stream；Worker 不可用时不能启动本地发布回退。

配置固定网络、创世根 txid、论坛服务公钥及真实连接地址。验证创世 raw 和签名后才建立可信浏览入口。分页保留服务端顺序，游标绑定论坛、操作、父节点与视图世代；切页、失效或取消不能混入旧响应。

## 内容

正文最多 1 MiB，附件最多 32 MiB，两者分别限制。MSFile 负责完整性与持久内容，Forum 只持有 hash 和展示投影。Markdown 不执行 raw HTML，不自动请求外部图片；附件先经 MSFile 验证，Window 再生成页面资源 URL。

MSFile 发布可达性与链上发布分别展示。卖方未就绪时如实显示不可达，不能用本地文件存在或下载来源代替他人可取用的证据。

## 发布与金额

发布按正文准备、父节点验证、签名报价、预算确认、专用资金准备、重新询价、固定布局构建、raw 校验和中心广播推进。金额分别列出 MSFile 费用、资金准备矿工费、索引费、父作者金额和协议矿工费。

钱包先用普通 P2PKH 交易准备专用 UTXO，正常找零；Forum 协议交易只消费所需专用资金。协议交易没有额外找零，差额只能在已确认的矿工费预算内。报价变化需要重新确认，不通过加大索引费或打赏消化余款。

P2PKH Worker 使用原资金记录、输入 claim 模型与中心广播出口。最终 raw、canonical txid 和提交编号构成持久证据，派发前写未知状态。广播、链上确认与 Forum 索引是独立观测；未知结果按原提交对账，不重建第二笔付款。changetip 的事件接受证据无法由当前节点接口精确证明，界面保留该限制。

## 取消与回收

取消、发布和资金回收共用派发租约。只有钱包证明同一提交明确未派发，且预签名释放成功，才能标记取消。已取消任务回收成功后仍保持取消状态，保留历史提交编号；未知或已派发提交不能释放占用。

专用资金回收与自有 data/tip 输出归集均为显式领域操作。归集重新取得真实 prevout，核验交易 ID、输出坐标、金额、归属及完整脚本，再按完整 scriptCode 签名。花费帖子 data 输出不删除帖子。只有明确接受广播才清对应资金记录；拒绝和未知保留证据与保护。

## 验收边界

协议黄金向量、持久恢复、保护门禁及真实 MessagePort 代理有本地回归证据；真实 Chromium 已验证双页共享配置、同 Worker 实例、锁定撤权和解锁恢复。真实 Go Forum + PostgreSQL 的 HTTPS 发布/索引/阅读冒烟，以及双客户端 BitFS 帖子购买冒烟已通过。Forum WSS/Direct、正式部署 TLS、浏览器重启、资金竞态与完整验收矩阵仍待验证。证据以[覆盖矩阵](./集成测试/覆盖矩阵.yaml)为准。
