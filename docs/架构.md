# Keymaster 架构

Keymaster 使用正式 `webloom-framework@0.6.0`。插件按领域归属扁平装配，manifest 不再包含产品等级、用户启停意图或启动阶段。发行版选择决定哪些产品参与系统；实际依赖、存储绑定及钱包会话条件决定运行单元是否可用。

## 领域与界面归属

| 包或位置 | 职责 |
| --- | --- |
| `packages/contracts` | 公共能力、领域数据、运行单元和 UI 注册契约；不导出 Storage 浏览实现或私有授权凭据 |
| `packages/runtime` | WebLoom 适配、实例签发核对、资源所有权及通用受限绑定；生产 Host 不持有领域注册表快捷入口 |
| `packages/plugin-page` | 路由、外壳、首页/通用设置/BSV 链设置容器、导航、通知和 UI 注册/渲染；每项贡献使用贡献实例的 consumer |
| `packages/platform-storage` | 存储引擎、用途绑定、恢复和 Storage 内部 UI；产品 id 为 `storage` |
| `packages/plugin-vault` | 密钥与会话能力、Worker 私钥缓冲和操作式密码学，以及初始化、解锁和密钥设置 UI |
| `packages/plugin-assets` | 资产/Token 注册表、失效通知、持仓聚合、资产列表/详情和首页卡片 |
| `packages/plugin-collectibles` | 藏品与转移处理器注册表、藏品列表/详情/转移 UI |
| `packages/plugin-scan` | 统一扫码/图片/粘贴入口，以及按真实 consumer/Scope 绑定的 URI 注册与分派 |
| `packages/plugin-p2pkh` | 普通 BSV 钱包、交易详情、`/transfer` 转账、身份/地址二维码及转账/受保护 outpoint 注册表 |
| 其他 `packages/plugin-*` | 各自的服务、存储用途、资源和 UI；跨包使用明确声明的能力 |
| `apps/web` | 可信入口装配、Coordinator 连接、授权登记与最低限度启动兜底 |
| `packages/ui` | 无领域权限的通用展示组件 |

`/settings/storage` 属于 Storage 内部 UI。全钱包浏览使用 Storage 包内契约、私有 Context 和同插件 Window → Worker 私有 RPC；普通插件不能获取浏览句柄，公共 Coordinator 不接受浏览命令。

Poker 按用户要求整包删除，不再参与产品目录、运行单元装配、API 或 UI。没有为此清除既有钱包中的持久数据。

## 页面贡献

贡献方声明 `page.ui.registry@1`，使用自己的真实 consumer 和 Scope 取得框架注册视图。Page 私有注册表拥有可执行条目，不公开组件、consumer 或私有 Context 列表。公共 renderer 只提供页面、设置块、header、框架和首页卡片的渲染出口。

页面、卡片、设置块和 URI 回调统一通过 `ScopedPluginConsumerProvider` 清空完整 Host/App Context，再以贡献实例 consumer 挂载，领域资源读者由贡献方私有 Context 持有。撤销时立即撤下贡献，缓存节点不继续执行，旧实例清理不能移除替换实例。页面路径和框架槽位冲突会被拒绝。当前正在显示的贡献撤下后，由 Page 返回诊断页。

业务导航登记只包含入口信息，组件与首页投影使用 Page 的独立 UI 注册。首页继续保持 main/aside 双栏、业务空间分组与原有排序。

## 执行环境与寿命

| 执行环境 | 职责 |
| --- | --- |
| Window | 界面、用户交互，以及必须在页面中执行的网络通道 |
| Coordinator SharedWorker | 多页面唯一的钱包权威、会话、权限租约、任务及最终 I/O 协调 |
| Service/Dedicated Worker | 媒体桥或隔离计算，不成为第二个钱包写入/签名权威 |

`units[].runtime` 表示执行环境，`scopeKind` 表示 root、storage、owner-session 或 connect-session 寿命。它们不授予领域权限。同一产品的 Window 和 Worker 是不同实例；依赖声明及槽位绑定确定实际提供方，代理存在不等于远端服务已就绪。

锁定、重置、断线或身份替换先撤权，再等待清理。异步结果复核会话和钱包世代，不能写入新会话。未知结果的不可逆操作不自动重放。

Vault 的 Worker 密钥会话持有私钥缓冲；替换/锁定时清零。Coordinator 调用摘要签名、地址派生、Channel 签名/解密与本地秘密派生等操作，不再读取活动私钥字节。最终 I/O 租约与请求授权仍在 Coordinator 边界核对。

## 能力、授权和存储

完整 Host、Context 与控制 hooks 仅从可信 `@keymaster/runtime/assembly` 接入，业务主入口不导出，插件代码门禁禁止该装配入口及原始全局 Context。插件只能消费单元明确声明的能力。Storage 文件/K-V 客户端与 Coordinator 客户端使用显式绑定能力，核对真实 consumer、Scope、插件身份和用途；缓存方法、订阅及异步完成同样受撤销约束。

领域注册表由对应插件提供，实例登记使用框架的归属视图。资源注册和读取只允许本实例定义，跨插件观察使用明确的服务或 reader。资产失效由 Assets 提供的通知能力发布。

MSFile 的 Web/Worker 服务及 Protocol 类服务只发布冻结的契约方法门面，不携带内部 Coordinator、依赖对象或原型方法。Vault 的密码学子句柄额外捕获提供方 Scope，每次操作及结果交付复核，提供方撤销即失效；会话不变或新实例恢复也不会复活旧句柄。

第三方 App 通过 Connect 授权入口消费批准的方法与受限存储，不进入内部插件容器。App 的稳定存储身份、路径及现有协议语义保持不变。

## 代码与迁移状态

- 发行版装配：`apps/web/src/pluginCatalog.ts`、`runtimeUnitImplementations.ts`。
- 公共运行单元目录：`packages/contracts/src/pluginProducts.ts`。
- Worker 单元及任务：`apps/web/src/coordinator/workerUnitCatalog.ts`。
- 通用适配：`packages/runtime/src/keymasterHostAdapter.ts`。
- 可信客户端绑定：`apps/web/src/assembly/coordinatorClientBindings.ts`。
- UI 注册与渲染：`packages/plugin-page/src/pageRegistry.tsx`。
- Storage 用途：`packages/contracts/src/storage/systemStorageDeclarations.ts`。
- Worker 密钥归属：`packages/plugin-vault/src/workerKeySession.ts`。

迁移仍在进行。静态目录已统一物化；Storage 已拥有显式客户端工厂、物理 I/O 队列、数据执行器和 Worker 句柄；Vault 已拥有钱包生命周期、KeyHold 仓储及 Key 投影；Connect 已使用明确的提供方名单和受限 App 绑定。Coordinator 其余领域 handler/task 归包、Worker 领域能力的真实消费，以及最终外部/不可逆 I/O/生产交接验收仍需完成。具体实施证据及未验收项见 [WebLoom 0.6 施工单](./proposals/webloom-0.6/Keymaster扁平插件迁移施工单.md)，不能以框架升级或部分门禁通过替代整项迁移验收。

## WebLoom 0.6 本地收口

Vault 冷启动通过 Storage 的私有装配端口：固定 KeyHold get/put，以及只允许三个初始化对象的原子 batch、readMeta/reset。该端口不发布为公共 capability，Vault 不能列举、Range 读取或管理存储连接；它在解锁前工作，避免 Vault 与解锁后 Storage scope 相互等待。Background、Contacts presence、P2PKH 快照和 Sat 连接状态由所属包持有，Coordinator 仅接权威和最终 I/O 回调。

Vault 的 Hex、WIF、JSON 解析器与 Key Import 向导已合并为内部 UI，不再作为独立插件装配。创建/导入、改名、改密、KeyHold 导出和重置仅由 Vault 内部服务与私有 React 上下文访问；公共 vault.service 显式发布白名单对象，不能访问内部服务或 Coordinator。公共 ActiveKeyCrypto 也不再提供密钥备份导出。

`/settings/plugins` 展示发行版插件依赖图，箭头从调用方指向提供方；Page 和 Vault 连线默认隐藏，可分别手动开关显示。点击插件节点后，弹框以“调用函数 → 服务方法 → 提供插件”展示正向或反向依赖，并提供源码文件/行号、环境、搜索及提供方跳转。此页不展示 enabled/disabled 或提供手动启停。函数数据由 `scripts/generate-plugin-function-dependencies.mjs` 使用 TypeScript 类型与调用点生成，只含静态事实，不持有服务对象；无法静态解析的动态/注入调用不伪造函数关系。`generate:plugin-dependencies` 更新数据，`check:plugin-catalog` 同时检查其与源码一致。

Settings 和 Home 独立插件已删除。Page 拥有 `/`、`/settings/plugins` 和 `/settings/system-status` 的容器及导航；扫码入口归 Scan，身份与地址信息归 P2PKH；Assets/Collectibles 分别持有聚合业务。业务设置块仍归各领域插件。当前发行版包含 21 个产品、32 个运行单元；Workspace 独立插件已删除。

URI 扩展遵循 [统一扫码与 URI 分派设计](proposals/webloom-0.6/统一扫码与URI分派设计.md)。Scan 只取得解析摘要，处理器和可执行 UI 留在内部；业务界面使用提供方 consumer，解析标识绑定请求实例和 Scope。输入不落盘、不记录日志。匹配不会触发联系人写入、消息发送、交易签名或文件购买；用户选择后进入领域 UI。


## 单 Key 钱包状态

Vault 的 `vault.wallet-state@1` 是唯一只读钱包状态能力，Window/Worker 根单元在锁定时也提供。Worker 从已提交权威状态投影，Window 复用 SessionStateMirror；状态和公开元数据来自同一修订。消费者按声明与真实实例 Scope 绑定，只获得 snapshot/subscribe，撤销后旧视图不能复活。Keyspace 服务、隐式 provide 接线和重复公开快照接口已删除，资源身份刷新由可信装配提交 runtime identity；其中包括 sessionEpoch、runGeneration、walletGeneration。

同一 Key 再次解锁会使旧工作失效。资产、消息、连接和授权表单在异步结果提交前复核完整会话；公开身份读取不能替代签名或存储授权。详见[钱包状态 API](钱包状态API.md)与[施工及验收记录](proposals/webloom-0.6/单Key钱包状态收口施工单.md)。
