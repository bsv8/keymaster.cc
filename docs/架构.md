# Keymaster 架构

## 分层

```text
应用层      首页、设置、联系人、消息、资产、扑克、外部 App
平台层      Vault、Connect、Storage、后台任务、Channel、MSFile
基础设施层  WebLoom Runtime、Coordinator、受限存储、P2P、WOC
```

`apps/web` 只负责装配和浏览器入口。`packages/contracts` 定义跨包契约；
`packages/runtime` 适配 WebLoom；每个 `plugin-*` 包拥有自己的业务和界面。

## 三个执行位置

| 位置 | 中文职责 |
| --- | --- |
| Window（页面） | 渲染界面、接收用户输入，以及执行必须依赖浏览器页面的网络能力 |
| Coordinator SharedWorker（共享协调器） | 多页面唯一的桶、Owner 会话、任务、存储授权和服务运行态 |
| Service/Dedicated Worker（专用工作线程） | 媒体 Range 桥、隔离计算或单次会话能力；不成为第二个系统真值 |

跨位置只传可校验的数据和受限服务代理，不传插件上下文、Provider、密码或私钥。

## 运行作用域

```text
root
└─ storage（当前桶）
   └─ owner-session（当前 Key 会话）
      ├─ plugin-instance（插件实例）
      ├─ connect-session（外部 App 会话）
      └─ request（单次请求）
```

子作用域不能活过父作用域。锁定、切 Key 或切桶时先撤销授权，再等待可等待的清理；
外部结果未知的操作不自动重放。

## 稳定边界

- 私钥操作只能通过 Vault 的操作式能力执行，业务代码不能读取私钥字节。
- 插件只能使用 manifest 明确声明的能力和存储用途。
- 菜单、路由和首页入口由插件注册，不在 Shell 重复维护。
- WOC 请求统一经过 WOC 服务。
- Window P2P Host 只有一个执行租约，MSFile 和 SatSubscription 复用不同 lane（网络通道）。
- Storage、Owner、插件和请求都带世代；迟到响应不能写入新会话。
- 第三方 App 只能通过 Connect 网关使用批准的能力，不能进入内部插件容器。

## 代码真值

- 产品和运行单元目录：`packages/contracts/src/pluginProducts.ts`
- Web 装配入口：`apps/web/src/pluginCatalog.ts`
- Worker 运行单元：`apps/web/src/coordinator/workerUnitCatalog.ts`
- 跨包能力：`packages/contracts/src/`
- 存储声明：`packages/contracts/src/storage/systemStorageDeclarations.ts`

文档只解释稳定关系；具体类型、默认值和字段以这些代码为准。
