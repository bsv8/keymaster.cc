# 插件生命周期

Keymaster 使用正式发行的 `webloom-framework@0.6.0` 管理运行单元、依赖、实例、consumer 和 Scope。发行版中的插件全部登记；没有产品等级、启动阶段或用户启停意图。业务配置（例如 MSFile 卖方接单开关）继续属于业务服务。

## 定义与装配

每个产品的 manifest 声明 Window/SharedWorker 单元、作用域、提供和消费的 typed capability、存储用途及明确发布的 Connect 方法。同一 runtime 中每个产品选择一个单元。`pluginCatalogSource.ts` 是 Window 发行选择与实现绑定的来源；`materialize-plugin-catalog.mjs` 将真实 manifest 物化为 Worker 可读的静态事实，检查陈旧产物。Worker 实现单独装配，不能通过导入 Window UI 后过滤实现隔离。

完整 Host 仅供可信装配使用。setup 获得真实单元的 consumer 与 Scope；业务 UI 使用该实例的 Provider 和私有 Context，资源定义及读取归该 consumer。跨插件操作必须声明 capability；资源缓存不能成为未声明服务的回退。

## 就绪与诊断

框架负责来源解析、依赖等待、实例创建、撤销和重试。钱包锁定、存储根及会话代际是 Keymaster 的运行条件；Worker 单元的实际服务与任务状态通过推送快照供诊断和业务依赖判断。登记授权或构造代理不能证明服务已就绪。

`/settings/plugins` 展示实际状态、依赖原因与恢复入口，不提供启停按钮。未启动的单元没有实例标识，界面不能编造实例或把 App 构造成功当成整个钱包可用。

MSFile 卖方开关只控制接单业务。开关开但依赖不可用时保持 `waiting-dependency`，订阅依赖变化后恢复；不得要求用户重切开关。业务开关不改变插件产品是否装配。

## 界面和注册归属

Page 拥有布局、路由、设置容器、首页卡片和正式 frame。贡献方通过其签发 consumer 登记；每项可执行内容以贡献方 consumer 挂载。注册表核对实例归属和冲突，撤销后旧回调、迟到结果和旧注销不能影响新实例。Host 只绑定通用实例注册机制，不拥有领域注册表或读取它们的全局 getter。

Storage 的全局浏览只在 Storage 私有 Context 中使用跨单元私有能力。Vault 的初始化、锁定和 Key 管理 UI 属于 Vault；Connect popup 属于 Protocol。Page 不反向依赖这些领域服务。

## 存储与密钥

Storage 的文件/K-V 客户端核对 consumer、单元声明及 purpose，Scope 撤销后缓存句柄失效。App 客户端只接受已验证的 Connect 会话事实，Storage 推导 module 和 App 目录；Worker 在每次 I/O 时再次验证权威会话、origin、Owner 和代际。

Vault Worker 独占明文密钥缓冲与密码学操作。钱包生命周期、KeyHold 和 Key 仓储实现归 Vault，底层 IndexedDB 事务归 Storage。对外提供操作，不提供私钥读取器；替换和锁定清零原缓冲。

## 撤权顺序

锁定、钱包重置、重新导入或实例释放时执行：阻止新请求，推进 epoch/generation，撤销代理和租约，等待有界在途操作，释放网络、监听和 UI 注册。

`sessionEpoch` 是会话代际，`runGeneration` 是 Worker 运行代际，`walletGeneration` 是钱包存储作用域代际。最终存储、签名、广播和付费 I/O 必须再次核对它们。清理失败可以报告，但不能恢复旧授权；迟到结果不得提交到新会话。

## 跨页面唯一运行

WebLoom 0.6.0 负责 SharedWorker Host、物理 peer 生命周期和 typed capability
撤权，但不提供跨物理 Worker 的 Runtime Lock。Keymaster 在 Worker 初始化、公开
Coordinator capability 和进入 final-I/O 前，必须取得自己的 origin 级 Web Lock：
`keymaster.coordinator.authority:v1`。这把锁从 Worker 启动保持到退场，所以旧/新
构建使用不同 Worker URL 时也只能有一个物理 Worker 成为 authority；锁冲突或原生
Web Locks API 不可用都必须 fail closed。

peer/session、lease、epoch/generation 继续负责页面会话、撤权、排空和迟到结果；
它们不是跨 Worker authority 的替代品。

页面端的 `keymaster.page-presence:*` Web Lock 只用于尽力判断“是否仍有其它页面在场”，
帮助刷新后的唯一页面回到锁定态；它不能代替 Worker authority lock、会话撤权或存储 CAS。
页面 presence 缺失时可以保持兼容行为，但 Coordinator authority lock 缺失时不能启动。

## 升级和未知结果

- 从旧版本升级时，必须先确认旧页面和 Worker 已排空退出，再启用新版本；新包不能抢占
  仍持有 `keymaster.coordinator.authority:v1` 的旧 Worker。
- 冷切换和回退都必须经过 authority Web Lock、final-I/O lease、traffic drain 以及现场交接证据；
  WebLoom 的 peer 事件只报告物理连接变化，不能替 Keymaster 选择 owner。
- Worker 崩溃后远端请求可能已经成功；广播、上传、订阅和支付必须按领域记录对账，不能
  因为新的 Worker 启动就自动重放。

## 发布门禁

本地生命周期、registry 安装和 Chromium 主链已有自动化入口。正式发布还必须使用
目标 Build ID 验证外部 AppView、不可逆 I/O、Coordinator 恢复和旧 Worker 退出证据：

```bash
pnpm test:e2e:lifecycle
pnpm verify:lifecycle-release
```

缺少外部环境时应保持“未执行/阻断”，不能用本地测试替代生产验收。

发布时先运行 `pnpm prepare:lifecycle-evidence` 生成证据骨架，再填写
[部署交接模板](./集成测试/资源配置模板/部署交接.json.example)，不要另建施工单。


## 钱包状态视图生命周期

Vault 根单元发布 `vault.wallet-state@1`；消费视图绑定真实 consumer、精确 Scope 与提供实例，读取、订阅和回调交付均检查有效性。消费方或提供方撤销时退订，实例替换后重新绑定。Window 的状态投影来自 SessionStateMirror，拒绝旧修订和已退役运行事件；Worker 的提交源不另立身份状态机。基线同步交付、重复快照去重、重入通知排序和观察者错误隔离由状态源保证。

业务工作的失效键是 status、公钥、sessionEpoch、runGeneration、walletGeneration；不能只比较公钥。runtime identity 的显式转换负责撤销并重建会话/存储单元及刷新资源，插件 provide 不再截获身份服务。详细契约见[钱包状态 API](钱包状态API.md)。
