# 存储桶与中央存储 V1 验收报告

> 更新：2026-09-14
>
> 范围：中央声明注册表、桶/Owner/浏览器公共存储边界、Coordinator 装配、Hold 唯一真相、full-head K-V 和 multipart 恢复元数据。

## 1. 完成定义

以下条件全部满足，才允许将 V1 视为完成：

| 项目 | 验收要求 |
|---|---|
| 中央声明 | 每项声明精确包含 module、purpose、scope、authority、model、schemaVersion；无未注册内置声明 |
| 访问边界 | Host/Coordinator 发放受限 Store；插件不接触 Provider、S3 SDK、浏览器存储或物理路径 |
| 数据归属 | 浏览器公共存储、桶、Owner 和内存边界清晰，数据不跨边界复制 |
| 插件意图 | `coordinator/plugin-intent` 是启停状态唯一持久化来源，失败时不先改变内存投影 |
| Storage Runtime | 只使用注入桶 Provider；不持久化 Provider 选择、切换记录或连接配置 |
| Vault | 普通 K-V 只有认证元数据、公开 Key 索引和删除事务日志 |
| Hold | `.keymaster/hold/v1` 是私钥密文唯一真相，Key 操作均经 Hold adapter |
| 句柄 | Coordinator 关闭自己打开的中央句柄；插件 Repository 不关闭 Borrowed Store |
| K-V | 只有 full head 和唯一 value 对象；写入不产生不可变历史对象 |
| GC | 低频按注册表枚举并保护旧 reader；普通写入不调用 list、不等待 GC |

## 2. 中央声明验收

平台中央声明应包含：

```text
coordinator/selection
coordinator/settings
coordinator/plugin-intent
storage/profile-salt
storage/multipart-uploads
protocol/durable-policy
protocol/sessions
protocol/command-history
vault/auth-metadata
vault/key-index
vault/key-lifecycle-journals
```

普通插件声明继续使用同一注册表。多用途模块必须按 purpose 精确解析，不能用任意第一项代替。第三方模块只能从已验证身份派生。

## 3. 生命周期验收

### 3.1 首次初始化

```text
构造桶目录记录
  → 测试 Provider 的读写和 CAS 能力
  → 暂存 Root、中央句柄、Hold 和首个 Key
  → CAS 发布桶对象与本机选中项
  → 安装 Coordinator 运行态
```

任一阶段失败都必须关闭暂存句柄、释放临时密钥并保留可重试的公开恢复记录；不得发布半成品当前桶。

### 3.2 锁定、切桶和改密

- 锁定先推进 session epoch、撤销授权、清理内存私钥，再处理可等待的后台清理。
- 切桶先认证和暂存目标绑定，成功后一次性替换当前 Root、Provider、中央句柄和会话。
- 改密先认证当前 Hold，CAS 发布完整下一代 Hold，随后更新认证元数据和公开索引。
- 密码、解密上下文、私钥和 S3 凭据不进入日志、事件或持久化运行状态。

## 5. 重点回归场景

- 同一 partition 的旧 reader 仍可完成旧 head 指向的读取。
- 新 writer 发布新 head 后，grace 期内 GC 不删除旧 value，grace 后才删除。
- 写入全过程 `listCalls === 0`，GC 不在普通写入路径同步运行。
- 没有长期打开句柄的桶级或 Owner namespace 也能由注册表枚举并回收 crash orphan。
- Hold 发布成功而公开索引写入失败时，下一次启动能够从 Hold 重建索引。
- 插件仓库关闭后底层 Borrowed Store 仍由 Coordinator 管理，切桶/锁定后旧句柄 fail closed。
