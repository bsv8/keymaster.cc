## 1. 已交付的程序路径

- Local 使用 `localStorage`，由页面桥在执行点校验 authority、lease、桶 ID 和桶世代；S3 物理根包含稳定的 `bucketId`，不同抽象桶不会共用对象路径。
- 桶目录只保存桶元数据和加密连接记录；桶内 Hold 提交快照是新版桶私钥密文的唯一真值，公开 Key 索引不含私钥密文或 `keyholdDocument`。
- 新建或导入桶先在目标 Provider 中提交首个 Hold 快照，随后才以一次目录 CAS 加入桶并（必要时）设置 `selectedBucketId`；初始化失败不会暴露半成品目录项，也不会按目录猜测删除其他标签页的桶。
- 跨桶切换先认证并暂存目标 Provider/Root，再执行目录 CAS 和 Coordinator 绑定；失败时保留旧桶或进入明确的 fail-closed 状态，不直接改页面目录。
- 当前桶禁止直接“移除连接”或“销毁数据”；当前桶改名走 Coordinator 的目录 CAS，非当前桶才允许普通连接移除或显式物理销毁。
- Worker 不再长期保存 `passwordKey` 或 `vaultLocalSecretKey`；应用本地 secret 使用当前 active Key 的临时 HKDF 派生密钥。旧 v2 secret 不自动猜测迁移，要求显式重新封装。
- 桶改密、连接配置修改、Key 新增/导入/删除和冷导出均走新版桶级快照路径；旧 OPFS/Profile 路径保留为兼容路径，不与新版目录静默混用。
- 管理页提供旧版识别、加密 Storage Profile 导出、旧 OPFS KeyHold 逐项导出；新版目录导入可将旧单 Key KeyHold 作为一次性迁移材料重新封装到 Hold 快照，原旧数据不自动删除。
- 新版桶目录存在时，旧版顶栏 Key 菜单运行时隐藏，由“桶 → Keys”树提供唯一入口；没有新版目录的旧 OPFS/历史单桶模式仍保留旧菜单作为兼容 fallback。
- Header 已提供“桶 → Keys”树：未解锁桶只显示“输入密码读取 Keys”，不使用本机 Keys 缓存冒充列表；当前 Key 有明确标记，同桶切换会弹出桶密码对话框并清理输入。
- 管理页明确区分“移除连接”（保留桶数据）与“销毁数据”（逐对象删除后再移除连接）；销毁操作校验桶身份、ETag 和当前桶保护。Local 会删除目标桶的全部可见对象；S3 只删除当前 List 可见对象，版本历史、Delete Marker 和未完成 multipart 可能仍保留，界面不再宣称不可恢复。

## 4. 旧数据处理操作单

1. 进入“存储桶”管理页，若检测到旧 OPFS 或旧 Storage Profile，先使用“导出旧 Profile”或逐把“导出 KeyHold”。
2. 创建并测试新版 Local/S3 桶；确认新版桶可正常读取和导出 Hold 快照。
3. 进入“Key 管理”，逐项导入旧 KeyHold 文件；导入时分别输入源文件密码和目标桶密码。新版导入会重新封装到桶级 Hold 快照，不会把旧 `keyholdDocument` 写入新版索引。
4. 验证新桶和业务数据后，再由用户自行决定是否清理旧 OPFS/Profile；程序不提供静默删除或自动覆盖。

旧 Storage Profile 只导出加密 envelope，不在导出按钮中解密凭据。旧 OPFS 没有完整桶级 Hold 文件时，必须使用逐 Key 导出；应用/插件业务数据不随 KeyHold 文件迁移，需另行确认其归属和备份范围。
