# 存储桶、Keys 与会话设计

> 更新：2026-09-07
>
> 状态：主要程序路径已按本设计实施；真实浏览器多页验收证据待补。
>
> 对应施工单：[001-存储桶外层管理与密码生命周期改造](../../施工单/2026-09-07/001-存储桶外层管理与密码生命周期改造.md)。
>
> 本文对 Local 后端、密码归属及存储失败处理的约定，替代旧文档中 OPFS 作为 Local、双密码、启动/运行期自动探测及失败跳转设置的约定。原有桶/Key/App 隔离、权限与旧请求失效约束继续保留。

## 1. 已确认需求

1. 存储桶属于整个系统的最外层，一个桶包含多把 Key。
2. 正式选项为 Local（浏览器 localStorage）和 S3；Local 不指 IndexedDB 或 OPFS。
3. 添加、导入、管理、删除和导出桶均在外层；Keymaster 的系统设置不再包含存储设置。
4. 密码属于桶：桶配置与该桶所有 Key 的私钥使用同一密码加密。不能为桶内 Key 设置独立密码。
5. 应用数据使用所属 Key 私钥对应的应用加密能力保护；实际算法和域隔离沿用或完善现有实现，不直接把私钥字节当通用对称密钥。
6. 本机持久化存储桶目录和加密配置；Keys、应用、插件信息保存到所属桶。
7. 桶配置接入 KeymasterHold；密码只用于当前解密操作，之后释放，不能长期缓存密码或可解密其他 Key 的密码派生材料。
8. 同桶切换 Key 必须再次输入桶密码；已解密的 S3 访问凭据可以在桶会话内继续使用。
9. 设置阶段测试成功、保存后，不再在启动、切换、网络恢复或业务失败时主动测试桶。
10. 实际读写失败就地报错；保存失败保留输入及保存按钮，允许用户反复重试。
11. 桶配置导入、导出统一使用 KeymasterHold SDK；全配置支持冷导出：不输入密码、不解密、不重新加密，组合已保存的完整密文快照并序列化。

## 2. 外层结构与导航

原 Header 的 Key 切换菜单改成：

```text
存储桶01 · S3
├─ Key01
└─ Key02
存储桶02 · Local（localStorage）
├─ Key01
└─ Key02
添加新的存储桶
├─ 新建
└─ 导入
管理存储桶
├─ 配置与名称
├─ 导出
└─ 删除
```

- 桶管理页面不依赖当前 Key、业务插件或业务系统已启动；首次进入和锁定时也能到达。
- 同时明确显示当前桶和当前 Key，避免不同桶内相同 Key 标签造成混淆。
- 桶列表来自本机配置目录；Key 列表来自对应桶，禁止把所有 Key 目录复制到本机配置。
- 冷启动时未解密的 S3 桶只显示桶名称及“输入密码读取 Keys”；不能假装已经知道其 Key 列表。
- 用户可以先解密桶并读取列表，再选 Key；本次密码上下文只维持该次进入流程，成功、失败、取消、离开或超时后立即释放。超时后选 Key 需重新输入。
- 运行中已有 S3 凭据时，读取列表复用该凭据；读取失败显示“读取失败／重试”，不回设置。

## 3. 数据归属

| 数据 | 保存位置 | 保护方式 |
|---|---|---|
| 桶 ID、显示名称、后端类型、配置版本、选中桶 | 本机 localStorage 的配置目录 | 最小启动元数据；不包含 Key 目录和明文凭据 |
| S3 连接参数及访问凭据、Local 配置记录 | 本机配置目录中的加密记录 | KeymasterHold + 桶密码 |
| Key 目录、标签、公钥、加密私钥及解密所需公开参数 | 所属桶的 Keys 区 | 私钥必须密码加密；公开元数据不等同于私钥 |
| Key 下的系统设置、应用、插件状态和数据 | 所属桶内对应 Key/App 命名空间 | Key 私钥派生、按用途隔离的加密能力 |
| 桶格式、版本、提交头、必要平台管理记录 | 所属桶的平台区 | 保留最少管理元数据，禁止夹带秘密或业务副本 |
| 密码、密码派生上下文 | 本次操作内存 | 不持久化，不进入日志、事件或长期状态 |
| 解密后的 S3 凭据 | 当前桶会话内存 | 桶关闭或会话结束后释放 |
| 当前 Key 私钥及应用派生材料 | 当前 Key 会话内存 | Key 会话结束后释放 |

Local 桶是明确的例外解释：它的桶数据本身就在 localStorage。这里仍区分“本机连接配置”和“桶数据”，而不是另建一份本机业务缓存。

建议物理命名空间（实现时版本化，所有字段附中文说明）：

```text
keymaster.storage.catalog.v2
  └─ 桶目录与各桶加密配置，不包含 Keys
keymaster.bucket.<bucketId>.*
  └─ 仅 Local 桶的对象、Keys 和应用数据
```

S3 桶的 Keys 和业务数据不得写到 Local 桶、旧 localStorage 键、IndexedDB、OPFS 或持久化离线队列作为兜底。语言、主题等现有浏览器业务偏好也要纳入归属审计；未选桶首帧可使用默认值或浏览器偏好，不新增独立持久化例外。

## 4. 密码与会话生命周期

### 4.1 首次使用「桶01 → Key01」

```text
输入桶密码
  → 解密本机桶01配置
  → 得到 S3 API 凭据并建立桶会话
  → 通过 S3 读取 Key01 密文
  → 使用本次密码上下文解密 Key01
  → 验证公私钥对应关系、记录归属及格式
  → 安装 Key01 私钥，建立 Key 会话
  → 清空密码输入，释放密码及全部临时解密上下文
```

随后运行期持有的是 S3 凭据和当前 Key 私钥，而不是桶密码。

### 4.2 同桶切换到 Key02

```text
重新输入桶密码
  → 复用内存中的 S3 API 凭据读取 Key02 密文
  → 根据记录中的公开 KDF 参数建立本次解密上下文
  → 解密并校验 Key02
  → 停止旧 Key 的任务和句柄，完成会话切换
  → 释放 Key01 私钥及其派生材料
  → 清理本次密码及解密上下文
```

这条路径不需要再次解密 S3 配置，也不能通过内存中残留的密码或派生密钥免密解密 Key02。

### 4.3 其他边界

| 场景 | 设计处理 |
|---|---|
| 新建或导入 Key | 输入桶密码并验证归属，用桶密码加密新 Key 后保存到桶；操作结束清理密码 |
| 解密失败或取消切换 | 清理临时密码与目标私钥，原 Key 会话保持；不把空记录当空桶 |
| 切换提交期间失败 | 不发布新 Key 为可用；按已完成阶段恢复原会话或留在明确的重试状态，不能混用两把私钥 |
| 切换到其他桶 | 输入目标桶密码，建立目标会话；成功切换后释放旧桶凭据、旧 Key 和旧句柄 |
| 读写失败 | 原请求返回错误；不销毁当前表单，不触发自动检查 |
| 刷新、关闭、完整退出桶 | 不持久化会话秘密；下次进入需输入密码。Worker 中的会话也须随退出协议释放 |
| Key 锁定 | 释放当前私钥及派生材料；是否同时退出桶见第 9 节建议默认值 |

无论成功、失败、取消、断开还是超时，清理都必须覆盖 `finally` 路径。不得把密码存入 React 长期状态、Coordinator 状态、闭包缓存、订阅回调、日志、全局事件或浏览器存储。输入组件只允许当前交互所需的短暂状态。

JavaScript 不保证立即物理擦除字符串的所有副本；验收要求是释放引用、清空输入、清零可控字节缓冲区、销毁 SDK 上下文，并证明没有可复用的密码解密能力残留。

## 5. KeymasterHold 接入边界

参考项目：`/home/david/Workspaces/KeymasterHold`，接口以其实际源代码及配套 SDK 文档为准。

- 使用分步 API：`createCryptoContext / deriveCryptoContext`（创建/派生临时上下文）、`encryptStorage / decryptStorage`（配置加解密）、`encryptKey / decryptKey`（单 Key 加解密），结束调用 `dispose`（释放上下文）。
- 同一密码不要求复用 nonce，也不允许以复用密码为由复用 nonce。同一桶用于完整 Hold 导出的记录必须共享同一组 `keyDerivation`（算法、盐和迭代参数）；仅密码相同而 KDF 参数不同的记录不能直接拼接。公开参数保存于快照头，记录通过快照版本关联它。
- 本机配置和桶内 Key 记录分开存储；Key 记录必须携带或引用独立读取时所需的桶级公开参数与归属信息，不能依赖本机持久化完整 Hold 文档中的 Keys。
- Hold 完整文档是全配置导入/冷导出的正式格式；日常配置不能因为 SDK 支持完整文档而把全部 Keys 放回浏览器。具体保存和导出规则见第 10 节。
- SDK 的结构校验不等于密码认证；独立记录加密认证不等于完整文档清单认证。接入时明确桶归属、公钥、版本和记录认证，禁止假称拆分后的记录仍具有原完整文档的认证覆盖范围。
- 新建 Key 时必须验证输入的是当前桶密码，不能只用任意输入加密并宣布成功。
- 现有逐 Key 密码、Passkey 绕过、缓存密码自动重加密和改密流程必须审计；不得保留能跳过“新 Key 重新输入桶密码”的入口。
- 桶改密涉及本机配置与桶内全部 Key，不能只改配置或单把 Key；跨存储提交与恢复方案是实现前置项，见施工单。

## 6. Local 的实现约束

Local 使用 localStorage，保持业务层统一的异步存储接口。localStorage 是 Window 上的同步 API，因此当前 SharedWorker 存储运行时需要经宿主页面桥接实际读写，而不能直接访问。参考 [MDN Web Storage API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Storage_API)。

设计约束：

1. Coordinator 继续负责桶身份、Key/App 权限与世代校验；页面桥仅执行经授权的 Local 物理存储操作。
2. 页面桥仅传输已经加密的秘密数据及允许的公开元数据，不接收桶密码和明文私钥。
3. `getItem/setItem/removeItem` 封装在 Provider；业务插件不得直接操作这些接口。
4. 跨页面“读取版本 → 比较 → 写入”使用同桶命名的 Web Lock；没有锁能力时明确报不支持，不能伪装成原子 CAS。锁语义参考 [MDN Web Locks API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Locks_API)。
5. 多对象提交采用先写不可变数据、再原子发布单一提交头的方案；不能认为多次 `setItem` 是事务。失败时旧提交头仍可读。
6. 桥接页面关闭、超时、QuotaExceededError、存储禁用都返回当前操作错误；重试不切换 Provider。
7. 延迟请求须在真正执行 I/O 的页面端再次校验有效租约/世代。桥接换页不能让旧页继续提交。
8. Local 容量和同步阻塞特性作为真实限制处理；文件类插件不得通过暗中使用 IndexedDB/OPFS 绕过限制。

## 7. 测试、保存与失败处理

### 设置阶段

1. 用户新建或编辑配置。
2. 点击“测试”；测试当前草稿的必要读写能力，不启动业务系统。
3. 测试成功后点击“保存”；只保存刚才通过测试的配置版本。
4. 参数、凭据或目标发生修改，原测试结果失效。
5. 配置持久化失败要明确报错，保留草稿和保存按钮；不能吞掉异常后显示已保存。

配置认证、格式校验、解密及读取实际数据不属于存储连接测试。它们仍在实际使用时执行。

### 保存之后

- 启动、进入桶、切 Key、页面可见性变化、网络恢复和业务读写失败均不触发测试。
- 不再使用后台健康探测、指数退避探测或全局存储 check 来决定是否返回设置页。
- 冷启动实际读取失败显示“读取失败／重试”，不得把已配置桶当成未配置桶。
- 认证密码错误显示输入错误；S3 凭据在实际请求中失效则显示请求错误，用户可以主动进入管理页修改。
- 不移除正常 CAS 冲突、授权、世代、格式或删除恢复校验；它们不是健康检查。

### 联系人保存示例

```text
编辑联系人 → 点击保存 → S3 PUT 失败
  → 显示“保存失败，请重试”
  → 对话框保持，输入内容保留
  → 结束提交中状态，保存按钮恢复可点击
  → 用户再次点击保存
```

重试使用同一逻辑记录 ID，避免“服务器已写入但响应丢失”时重复创建。并发冲突不能简单无条件覆盖，必须给出可重试或重新读取提示。

## 8. 配置和兼容边界

- 为配置目录、桶数据、Key 密文和导入文件分别标注版本。
- 旧 OPFS 桶不得悄悄映射为 Local，也不删除旧数据。
- 旧双密码桶不能直接当作同密码桶打开；实施前选择并明确交付转换工具或可操作的旧格式导出入口。
- 转换必须先验证旧配置和全部 Key 可读，再生成新记录，完整验证成功后切换引用；失败保留旧数据。
- 删除本机连接项与删除桶中实际数据是不同操作，界面和契约必须明确。
- “导出全部配置”指 Hold 文档包含桶配置与全部 Key 配置/私钥密文，不代表包含应用数据。完整数据备份是另一项能力，Local 的 Hold 配置文件不能恢复应用数据。

## 9. 建议默认值与待定事项

以下是设计建议，不冒充已经逐项确认的需求；施工时按最终确认更新本节：

| 事项 | 建议默认值 |
|---|---|
| 同时保留多少桶凭据 | 仅当前桶；跨桶切换成功后释放旧桶凭据 |
| 锁定粒度 | “锁定 Key”只释放私钥；“退出桶”同时释放 S3 凭据。自动锁定采用哪一种需明确 |
| 删除桶 | 默认只移除本机连接项；销毁 Local/S3 数据为单独明确操作 |
| 完整数据备份 | 本次已确认的是 Hold 全配置冷导出；是否另做包含应用数据的完整备份需独立确定 |
| 旧数据兼容 | 不自动迁移、不删除；提供明确版本提示及迁移/导出路径后再切换 |
| 桶改密 | 完整设计可恢复的批量重加密与跨存储发布；不得保留旧 Key 单独改密入口 |

## 10. KeymasterHold 全配置冷导入与冷导出

### 10.1 已确认目标与范围

用户操作“导出全部配置”时，不要求输入密码，不解密桶配置或任何 Key，不重新加密；通过 KeymasterHold SDK 输出包含桶加密配置和全部 Key 密文的标准 Hold 文件。

“全部配置”具体是 SDK 支持的 `StorageRecord`（桶配置记录）和 `KeyRecord[]`（Key 记录集合），连同文档头和认证信息。KeyRecord 中的标签、公钥按 SDK 格式保存，私钥放在 `cipher`（密文封装）中；不能声称 SDK 会加密它定义为公开的字段，也不能私自增加不兼容字段。Key 下的应用数据和插件业务数据不属于 Hold 配置导出范围。

### 10.2 当前 SDK 的实际约束

依据 KeymasterHold 当前 `src/types.ts`、`src/crypto.ts`、`src/format.ts`：

| SDK 字段或 API | 中文含义与约束 |
|---|---|
| `HoldDocument` | 完整导入/导出文档；包含格式版本、公共 KDF 参数、桶密文、Keys 集合和认证标签 |
| `keyDerivation` | 整份文档共享的密码派生参数，不能逐 Key 任意换盐后直接拼接 |
| `storage` / `keys` | 必须原样保留 SDK 规定的加密记录及公开字段 |
| `integrity` | 整份文档的 HMAC 认证，覆盖集合内容；更改任何受认证内容需重新生成 |
| `sealDocument(parts, context)` | 使用密码上下文组装和认证文档；当前实现还会逐条解密校验记录，不是冷导出 API |
| `serializeDocument(document)` | 无密码结构检查和序列化，不生成、不修复、不验证 HMAC |
| `parseDocument(input)` | 无密码严格解析外部文件；成功仅代表格式通过，不代表密码认证通过 |
| `openDocument / verifyDocument` | 输入密码或临时上下文后验证完整文档认证，用于实际启用前 |

因此，冷导出可以重新组合**同一个已认证快照原有的组成部分**；不能把任意最新记录拼起来，再复制旧认证标签冒充有效文件。不修改 SDK、不去掉 `integrity`、不长期保存 HMAC 密钥来规避密码生命周期。

### 10.3 保存模型：写入时准备，导出时组合

每桶维护已提交的 Hold 配置快照。它是配置记录的版本化组织方式，不是在本机额外缓存全部 Keys。

| 组成部分 | 持久化位置 | 保存内容 |
|---|---|---|
| 本机连接配置 | 本机桶目录 | 启动所需的桶密文、公共 KDF 参数和配置版本引用；不含 Keys |
| Hold 快照头 | 所属桶的平台配置区 | `format`、`version`、`keyDerivation`、`integrity`，以及内部快照版本和有序 Key 引用清单 |
| 桶配置密文快照 | 所属桶的平台配置区 | 与本次认证对应的原始 `storage` 记录，用于避免其他设备本机连接配置版本不同导致错误拼接 |
| Key 密文快照 | 所属桶的 Keys 区 | 本版本全部 SDK KeyRecord，保留认证所需的字段与顺序 |
| 提交头 | 所属桶的平台配置区 | 指向唯一完整可读的已提交快照 |

桶内保存配置密文快照只服务导出版本一致性；启动仍依赖本机加密连接配置，不制造“必须先连接才能解密连接”的循环。桶内部引用、提交头和世代是 Keymaster 管理元数据，导出时不作为额外字段塞入严格 Hold 文档。

修改桶配置、增加/删除 Key、更改 Key 标签、修改密码等会改变 Hold 认证内容的操作：

1. 本次操作输入并验证桶密码，建立临时上下文。
2. 读取当前完整配置快照，修改目标记录；公共 KDF 参数遵循该桶版本。
3. 使用 SDK 生成完整有效的认证文档，并将组成部分保存为新快照。
4. 全部写入成功后，CAS 发布新提交头；本机连接引用按可恢复协议收敛。
5. 释放临时密码、上下文及 SDK 校验产生的临时私钥；只保留当前会话允许持有的秘密。

删除 Key 或修改公开标签也可能因此需要密码，这是当前 SDK 整份文档 HMAC 模型带来的实现要求；不能无密码改完集合后让下一次冷导出输出失效认证。仅修改不属于 Hold 文档的本机显示元数据不需重算 Hold 认证。

修改失败不发布新快照。导出只读取已提交版本，不能导出半更新集合。普通应用数据写入不修改 Hold 配置认证，因此不需要桶密码。

### 10.4 冷导出流程

```text
点击“导出全部配置”
  → Local 直接读取 localStorage；S3 复用桶会话中的 API 凭据
  → 读取已提交快照头并固定该版本
  → 读取该版本的 storage、全部 keys、keyDerivation、integrity
  → 按 SDK 格式与原有顺序组合 HoldDocument
  → SDK serializeDocument
  → 下载加密 Hold 文件
```

- 不弹出密码框，不调用 KDF、解密、加密或 `sealDocument`。
- 导出与写入并发时，读取固定不可变快照；记录缺失、版本不一致或无法读取则报错重试，不能漏掉 Key 后继续下载。
- 不持有密码时只能检查结构与快照完整性，不能宣称本次导出已经重新验证 HMAC；密码认证在后续启用/导入验证时进行。
- 冷导出不等于离线可访问 S3。桶会话尚无 S3 凭据且密文只在 S3 时，无法读取配置集合；界面说明需先建立桶会话。导出动作本身不要求密码，也不为此在本机缓存 S3 Keys 或长期存储凭据。
- Local 在未启用 Key 时也可读取已提交的密文快照并冷导出，无须解密配置。

### 10.5 SDK 导入流程

1. 使用 `parseDocument` 严格解析 Hold 文件，保留原始 SDK 字段、公共参数、Keys 和 `integrity`。
2. 可以无密码读取公开摘要，但标为“未验证密码认证”；不据此启用桶或导入可用 Key。
3. 实际启用时输入桶密码，通过 SDK 认证文档并解密配置；这与无密码冷导出不冲突。
4. 将配置与 Key 记录按上述分层模型保存；不得把整个含 Keys 的 Hold 文件写入本机连接配置目录。
5. 新导入文件可作为临时内存材料，取消、失败或操作结束后释放。S3 密文落桶需要可用连接，不能在无法写入时宣称导入完成。
6. 保留公共 KDF 参数的完整性。合并到已有不同参数的桶属于带密码的转换/重加密操作，不属于冷拼接；不得自动处理为无密码合并。

同一已提交快照的“导出 → SDK 解析 → 输入原密码认证/解密”必须互通，并恢复全部配置与 Key。应用数据另按桶原有位置读取，不声称 Hold 文件包含应用数据副本。
