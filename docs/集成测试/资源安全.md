# E2E 资源安全规则

## 固定文件

真实资源只从仓库外的 `KEYMASTER_E2E_CONFIG_DIR` 读取，缺省为
`/home/david/.config/keymaster-e2e`：

| 文件 | 内容 | 处理方式 |
| --- | --- | --- |
| `s3.json` | 本次测试直接使用的 S3 目标和访问凭据 | 只由 Node Resource 读取 |
| `satsubscription.json` | WebSocket、WebRTC Direct 与 Node 侧 testnet 链 API 入口 | 只由 Node Resource 读取 |
| `seed-key.hex` | testnet 长期资金库私钥 | 只由 Node Resource 读取，永不进入浏览器 |

目录权限不得宽于 `0700`，三个文件不得宽于 `0600`；所有者必须是当前用户，文件不能是
符号链接，真实路径必须位于 Git 工作树之外。测试框架不会自动修改权限来制造“检查通过”。

## S3 删除作用域

S3 物理桶和连接信息直接取自仓库外 `s3.json`；不要求额外的 purpose、专用桶名称或
ownership 文件。配置目录本身已经是 `keymaster-e2e` 的 E2E 配置目录，当前运行仍需先取得
`.keymaster-e2e/lease.json`，避免两轮资源测试同时操作同一个桶。

前缀测试调用带 prefix 的清理，只处理自己的 `run_id/scenario_id/`；非前缀测试不传 prefix，
清理该桶中的全部业务对象。两种清理都分页处理普通对象、版本和 delete marker，中止 multipart
upload，并在当前清理期间保留 lease 控制对象；删除后再次分页确认。清理未确认时真实验收保持阻断。

`G-RESOURCE-SAFETY` 是真实资源 Gate：它使用 setup 已取得的 lease，在真实桶中创建两个本轮
prefix 对象，验证越界 prefix 被拒绝、前缀清理不影响另一个 prefix，并在自身结束前清理两处对象。
清理器的异常分页和边界分支由非 E2E 单元测试负责；它们的结果不能替代真实桶验收。

浏览器初始化还要求目标 S3 的 CORS 允许当前 preview origin（通常是
`http://127.0.0.1:4173`）访问 GET/PUT/DELETE/POST/HEAD，并允许 `Content-Type`、
`If-Match`、`If-None-Match`、`Range` 和 `x-amz-*` 请求头，暴露 ETag、Last-Modified、
Content-Range、Content-Length 等响应头；Node 侧能列桶不代表浏览器初始化已通过。

## testnet 资金门禁

资金管理器内部固定使用 testnet，调用者不能传入 mainnet。长期 seed 只用于派生 testnet
身份和 Node 侧充值/归集；每个资金 Journey 使用独立一次性钱包、预算和不含秘密的恢复账本。
广播结果未知时先对账，禁止盲目重发。恢复账本同时记录充值金额、业务转出金额、归集金额、
实际手续费、损失上限和最终状态；`uncertain`、未归集、账本损失超过上限或余额无法确认都会
阻断真实资源验收通过。

## 产物

真实资金场景不保留可能捕获输入私钥的 trace、视频、截图和 DOM snapshot。所有附件在上传前
经过 `e2e/integration/support/redaction.ts` 扫描；发现秘密时测试失败并禁止上传。报告只保留
脱敏后的地址、txid、金额、状态和错误码。账本文件采用受限权限并以原子替换写入，避免进程
崩溃留下半截恢复记录。
