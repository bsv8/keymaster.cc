# 初始化与存储

用户先选择逻辑桶，再完成密码和第一把 Key 的一次性初始化。Local 的浏览器 KV 真值是
`localStorage`；Coordinator Worker 通过页面 MessagePort bridge 访问它。初始化成功的条件
不是 URL 改变，而是完整 Hold 快照提交、目录 CAS 发布、运行态安装和刷新恢复都成立。

当前本地 Journey：`J-LOCAL-INIT-MENU`（生成 Key）、`J-LOCAL-INIT-IMPORTED`（导入 Hex Key）、
`J-LOCAL-CONTACT-MESSAGE`（初始化后继续进入联系人/消息）和 `J-LOCAL-P2PKH-NAVIGATION`
（初始化后继续进入资产页面）；真实资源 Journey：`J-REAL-S3-INIT`。
Local 首次初始化和刷新恢复已在真实 Chromium 冒烟中执行；S3 Journey 使用仓库外
配置中的已存在物理桶，在 `run_id/J-REAL-S3-INIT/` 前缀下建立 Keymaster 逻辑桶，
不会把“连接探测成功”冒充成完整初始化。真实 S3、CORS、跨页并发和目标部署是否
执行仍按覆盖矩阵记录。

S3 初始化的字段边界：`桶名称` 是用户看到的逻辑桶名称；`Bucket` 是 s3.json 指定的物理
S3 桶名称；`Prefix` 是本轮隔离的对象路径前缀；`Access Key ID` 和 `Secret Access Key`
只在浏览器本次表单调用中短暂使用。前缀 Journey 只清理自己的 prefix；非前缀资源收尾才
执行指定桶的全量业务对象清理。
