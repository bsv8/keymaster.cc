## 1. 当前职责

Keymaster 负责面向用户的公钥/交易教育、业务用途、对方资料/信用/风险、原有业务确认及权限检查。私钥后端管理密钥、检查实际支持操作并执行。硬件额外提供实体基础审核和许可/否决；软件检查通过且额度内直接执行，超额需要确认；不为对齐硬件增加额度内逐笔批准。

## 2. 固定顶栏与面板

保留固定顶栏钱包入口，可查唯一 Key/完整公钥、软硬后端、解锁/锁定、硬件连接和执行状态，不引入钱包列表。下拉面板可承载这些状态、主机业务说明和硬件等待；面板收起不意味着批准或取消，不能因组件开关产生签名。

业务说明可以在原业务页面展示，不要求全部迁入面板；不得同时在业务页和钱包面板复制同一软件确认。现有 App 权限、软件密码解锁、业务发送确认保持各自用途，避免把“无新增钱包确认”误作取消已有确认。

| 流程 | 软件后端 | 硬件后端 |
| --- | --- | --- |
| 业务解释/信用/Markdown | Keymaster 页面或面板展示 | 同样由 Keymaster 展示，设备不显示服务正文 |
| 已有确认与权限 | 检查通过后核验渠道额度 | 检查通过后送设备独立核验额度 |
| 支付基础审核 | 内部核验，额度内自动、超额弹窗 | 设备核验实际对象/金额/费用等，额度内自动、超额实体同意/否决 |
| 顶栏执行状态 | 执行/完成/失败/未知，无批准弹窗 | 连接/锁定/等待设备/拒绝/完成/未知 |
| PIN/私钥 | 软件认证入口，无设备 PIN | 设备输入，不在浏览器代输 |
| 持续决定 | 不新增镜像硬件授权菜单 | 设备适用的会话决定/撤销，主机显示真实已同步状态 |

主机预览不能声称设备已核验；硬件最终批准在设备。顶栏不为软件添加长按、逐项设备式审核或会话许可/否决框。软件 lock/撤权/世代变更后仍禁止执行；错误或结果未知不自动重试，签名与广播分开。

## 3. 外部信息

信用查询是 Keymaster 功能：语言 + 自由文本请求、Markdown 回复可为空，指标不结构化。来源验证、对象/操作绑定、错误和语言显示、正文安全和查询隐私方案由主机业务契约冻结。撤销“仅设备能解密”；不得继续建设设备密文转发/服务回复解密路径。

正文不改变真实收款/金额/权限/按钮，不执行 HTML/脚本；无信息不判安全/不安全。查询失败不伪造有效空结果，不新增信用成功才能签名规则。设备只显示实际操作基础事实，不依赖主机评价。

## 4. 当前验收

旧 KM-UI-01 至 10 及 U0–U6 完全对应任务取消，编号不复用。按 KM-MIN-01/02/03 验证：软件无新增确认且权限仍有效、Keymaster 外部信息正常、顶栏和硬件等待显示真实状态。窄屏/键盘/滚动及拒绝/锁定可达仍需 UI 验证，不要求软件仿照设备输入或布局。

只改文档，不表示已实现顶栏、信用服务或硬件支持。


## 5. 支付额度 UI 当前规则

额度内不新增批准；软件超额弹窗、硬件超额设备确认。App 确认展示单笔与会话累计/额度及所有原因，可拒绝、仅批准本次或提高本会话累计额度并本次。增额不改未来默认/渠道单笔，也不重置累计。私钥设置列出各渠道和 App 默认会话额度；硬件配置未确认不显示为已生效。以 PAY-01 至 07 为本增量验收。
