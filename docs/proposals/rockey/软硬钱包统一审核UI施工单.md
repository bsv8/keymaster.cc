## S0：边界与调用审计

- [ ] 区分业务确认、App 权限、软件解锁、硬件批准，记录实际调用文件；检查已有代码是否新增了设备式软件批准，若有则按确认边界移除，保留现有业务权限。
- [ ] 信用查询/Markdown 归 Keymaster 业务层，移除原软件 Worker/设备外部说明及镜像 UI 施工依赖，不新增 VLP 信用协议。
- [ ] 当前页面壳归 `packages/plugin-page/src/shell/Topbar.tsx`/`AppShell.tsx`，Vault 使用既有 manifest/页面贡献提供钱包状态，不能在页面组件复制授权真值。

## S1：顶栏状态和主机说明

- [ ] 装配固定顶栏/下拉状态入口：唯一 Key/后端、锁定/连接、执行/硬件等待/失败/未知；兼容窄屏、键盘、焦点和滚动。
- [ ] 业务说明和信用资料复用现有页面或面板，语言/自由文本、Markdown/空结果/来源绑定/网络错误在主机处理；不要求业务再次走钱包批准。
- [ ] 软件额度内直接执行不弹出允许/否决框，超额按 S4 弹窗；主机面板不得批准硬件，设备 PIN 不在浏览器输入。

## S2：后端及业务接入

- [ ] Vault/Coordinator 保留 owner/scope/App 会话/运行世代/锁定/撤权核验，软件检查通过调用 Worker，拒绝无授权调用而非“一律签名”。
- [ ] 业务原确认后分流软件/硬件；硬件核验真实操作与额度，超额等待物理决定；软件额度内无额外批准，超额按 S4 确认，操作改变不能复用旧硬件同意。
- [ ] BSV/费用池按 VLP 冻结支持集接入，无解析器项不可用，不偷偷走软件 fallback；签名/广播/未知状态分开。
- [ ] 硬件持续否决不循环弹窗，撤销以设备真实状态为准；控制/锁定可达，结果未知不自动重签。

- [ ] KM-MIN-02：主机信用查询/Markdown/空与错误、来源/对象绑定及安全显示；设备/USB 无服务请求或正文依赖。
- [ ] KM-MIN-03：硬件等待/否决/持续决定、BSV/费用池基础预览与独立核验，真实浏览器/设备证据单列。

旧 U0–U6、KM-UI-01 至 10 不再作为施工或通过门禁；不新增第二套软件授权 UI。
