> 状态：代码已实施，浏览器验收已执行（P01/P02/P07、L02、U01 有真实 Chromium 证据）；P03/P04 渲染与超大目录翻页仍未验证，见 §8 状态列与 §10.1–§10.3。日期：2026-10-01，审查修复 2026-10-02。
> 本单依据当前工作区的单 Key 本地存储实现和已确认需求编写；目录示例不代表已经读取实际钱包数据。
> 本次交付仅为施工文档，不包含功能代码。实现完成后，将稳定行为合并至 [存储](../../存储.md)，施工过程由 Git 历史保留。

## 1. 目标与范围

在「设置 → 存储」增加存储浏览器，建议路由 `/settings/storage`。用户可以沿树状结构观察当前钱包实际存储的文件、文件夹和内部对象，选中文件后预览 JSON、Markdown、TXT 等文本内容，并查看完整路径和元数据。

第一版包含：

- 树状目录与文件、当前目录列表、路径面包屑、路径复制、手动刷新。
- 文件大小、修改时间、版本和内容类型。
- JSON 格式化与节点折叠、Markdown 渲染及源码切换、文本预览及自动换行。
- 系统区、K-V 内部对象、snapshot、App 空目录、停用插件遗留数据的展示。
- 按需分页、预览大小限制、版本变化提示、锁定与重置后的失效处理。

本期只观察真实路径、文件属性和内容，不增加模块归属、用途、状态分类或中文目录别名等标注。不包含编辑、上传、重命名、移动、删除、备份恢复、全局搜索、媒体播放、MSFile 原文件重组，以及 K-V 垃圾回收或业务修复操作。浏览动作不得写入钱包；展开状态、选中项和预览内容仅保存在页面内存。

## 3. 页面设计

桌面布局：左侧文件树，右侧上部当前目录列表，右侧下部选中文件的「预览 / 属性」面板。页面顶部显示路径面包屑和刷新按钮。宽度不足时，文件树收为可打开的侧栏，保留目录列表、面包屑和文件详情。

```text
存储浏览器                                      [刷新]
路径： / contacts / address-book
┌────────────────────┬──────────────────────────────────┐
│ 文件树              │ 名称             大小     修改时间 │
│ ▾ /                │ 02ab….json       1.2 KB   …       │
│   key.json         │ 03cd….json       0.9 KB   …       │
│   ▸ .keymaster     ├──────────────────────────────────┤
│   ▾ contacts       │ [预览] [属性]                     │
│     address-book   │ JSON / Markdown / 文本内容        │
│   ▸ messages       │                                  │
│   ▸ msfiles        │                                  │
│   ▸ apps           │ 完整路径                 [复制]   │
└────────────────────┴──────────────────────────────────┘
```

交互要求：

1. 初始只展开逻辑根；系统区和内部目录可见但默认折叠。
2. 文件树包含目录和文件；点击展开按钮只展开，点击目录名称切换当前目录，点击文件选中并加载预览。
3. 当前目录只显示直接子项。文件夹先于文件；各组按稳定名称顺序排列，跨页合并后仍保持顺序。
4. 路径名称保持真实原文，例如直接显示 `contacts`；不添加中文别名或模块说明。
5. 长哈希和公钥可缩写，属性面板和复制内容必须完整；以完整路径作为节点身份。
6. 支持键盘展开、收起、移动焦点和选中；焦点状态与选中状态可区分。
7. 选中文件默认进入「预览」，属性显示完整路径、字节大小、修改时间、抽象版本和可用内容类型。
8. 空文件显示“空文件”；空目录、尚未加载、加载失败、未完成分页必须分别表达。
9. 手动刷新保留仍存在的路径与展开状态，重新获取列表及所选文件；文件已删除时清除旧内容并提示。

## 4. 文件树的真实性

- 节点来自实际对象路径，不从中央声明生成不存在的空文件夹。
- 一个逻辑对象只显示一次，不能把 `objects` 与 `objectIndex` 展示成两份文件。
- 显示 `key.json`、根 `.keymaster` 和模块内 `.keymaster`，包括 K-V head/value、旧值对象及恢复证据；浏览器不判断或清除垃圾。
- snapshot 的 `current`、没有扩展名的 MSFile 块必须出现。
- 插件停用、App 撤权后仍存在的数据保持可见，显示不依赖插件是否启动，不添加停用或撤权标签。
- 无法关联声明的对象仍按真实路径显示，不分类、不标记“用途未识别”、不过滤。
- `apps/<存储名称>` 只显示真实存储名称，不查询 App 显示名或推断身份。
- `.dir` 在主视图折叠为目录，目录属性列出标记对象的完整路径和元数据；物理对象统计中包含标记，文件数量说明排除标记。不能凭文件名推测任意业务对象为目录，需结合既有标记规则及内容类型。
- 若同一路径既有文件对象又有同名子目录，分别展示文件和目录，使用类型区分节点，不能覆盖其中一项。

第一版只要求准确显示文件大小和当前已加载子项数量。目录递归总数、总大小可不提供；提供时必须在扫描完成后才作为准确值显示。逻辑对象字节总和与浏览器 `usageBytes` 的磁盘占用口径分开说明。

## 5. 只读平台能力与 RPC

访问链路固定为：存储浏览页面 → 平台专属只读代理 → Coordinator → 现有 WalletStore。

新增独立的平台浏览契约和能力，不借用或扩大 Connect App grant，不向普通插件和第三方 App 发放根浏览权限。普通模块/App 的文件接口与命名空间栅栏继续有效。页面可以接收用于展示的逻辑路径，但不能获取数据库连接、底层仓库或任意存储句柄。

建议契约职责如下；名称可按现有框架调整，字段首次定义需附中文注释：

| 职责 | 输入与输出要求 |
| --- | --- |
| 打开浏览会话 | Coordinator 验证受信任的平台运行单元、页面连接、当前解锁状态；发放绑定钱包身份世代、会话世代、Worker 运行世代的临时浏览句柄 |
| 列举对象元数据 | 输入目录、游标和页大小；返回该目录前缀内的一页对象元数据、下一页游标；路径、大小、修改时间、抽象版本、可用 `contentType` 均不含文件内容 |
| 请求文件预览 | 输入完整逻辑路径、期望版本；Worker 强制字节上限，返回预览格式、内容或字节、完整大小、读取范围、截断状态和实际版本 |
| 关闭/取消 | 页面离开时释放句柄和请求；锁定、重置、Worker 重启或连接失效时统一撤销 |

权限由 Coordinator 已验证的运行单元/端口上下文决定，不能信任调用方自报的 `platform-only`、插件 ID 或路径。句柄、游标不得持久化。游标绑定目录和浏览会话，跨目录、跨端口或过期重放失败。

路径校验复用 `normalizeRelativeStoragePath` 等现有规则；显示根 `/` 在 RPC 中用单独的根表示转换，不作为合法绝对对象路径。目录前缀按路径段补 `/`，不得让 `apps/a/` 命中 `apps/a-evil/`。未知对象路径只要真实存在且属于当前钱包仍可浏览。

## 6. 分页与加载策略

第一版复用 WalletStore 的对象元数据分页：默认每页 200 条，页大小由 Worker 校验且不得超过现有底层硬上限。页面按所选目录前缀加载一页，折叠路径为直接子项，跨页按节点身份去重，并明确显示“继续加载”。

必须处理：

- 一个深目录可占满若干对象页，同一子目录可能在多页重复出现；不得把一页折叠结果当成完整目录。
- 某页折叠后可能没有新增子项，但仍有游标；继续加载入口必须保留。
- 点击尚未完全扫描目录中已发现的子目录，可独立按该前缀浏览，不等待父目录全量完成。
- 每个目录维护独立游标、已加载节点和完成状态；刷新失效相应缓存。
- 页面只保存已经请求过的元数据，不在打开时扫描所有字节或自动递归整个钱包；大量行使用有界渲染。
- 多页读取不是全钱包原子快照。并发写入后通过刷新重新观察，不声称当前统计与内容属于同一个全局时刻。

如后续优化为 Worker 直接分页目录子项，必须另行保证去重、子树跳过与游标语义；不得直接复制现有 Connect 对象页折叠逻辑并宣称是完整目录分页。

## 7. 文件内容预览

### 7.1 格式识别与呈现

优先验证已知存储信封，再依据可靠的内容类型、扩展名和有限内容检测选择预览。明确标记二进制的对象不得仅因扩展名为 `.txt` 就按文本呈现；无法判断时给出不支持提示。

| 格式 | 行为 |
| --- | --- |
| 完整 JSON | 格式化展示，支持节点折叠；保留原文查看入口；展示转换不得改变原文件 |
| 损坏 JSON | 显示原文和解析失败提示，不显示为空数据，不对存储执行修复 |
| Markdown（`.md`、`.markdown` 或相应内容类型） | 默认渲染，支持源码切换；以完整文件为渲染前提 |
| TXT 和其他可确认文本 | 等宽字体、保留换行、可切换自动换行；按文本显示，不执行脚本或 HTML |
| 无扩展名 JSON | `current`、K-V head 等也可正常识别并展示 |
| K-V value | 校验既有信封、版本及载荷哈希，提供解码内容和原始内容切换；JSON 载荷可预览，二进制载荷按不支持预览处理；保持原对象路径 |
| 二进制/未知格式 | 提示“此格式暂不支持预览”，属性继续可用 |
| `key.json` | 展示原有加密 KeyHold JSON；不调用解密或导出明文私钥能力 |

K-V 解码复用或提取当前引擎的纯解析函数，保留既有格式校验。遇到不支持的版本或损坏信封时提示错误并保留属性；不默默退化成一份看似正常的业务 JSON。解码后的二进制载荷仍不作文本预览。

文本第一版支持有效 UTF-8（含 UTF-8 BOM）；其他编码明确提示不支持，不静默替换非法字节。截取文本尾部可能落在多字节字符中间，需避免由截断造成误报或乱码。

### 7.2 大小与资源限制

- Worker 强制每次预览最多返回 1 MiB（1,048,576 字节）的原始内容，限制不能由页面绕过。
- 超限文本只显示截取源码，明确“已显示前 X 字节 / 共 Y 字节”；本期不提供绕过上限的全量加载按钮。
- 截断 JSON 不执行结构化解析，截断 Markdown 不执行渲染；截断 K-V 信封不声称已完成哈希校验或成功解码。
- JSON 树使用按需展开和有界节点渲染；深层 JSON、长单行、Markdown 解析应具备有界工作量或可终止的解析任务，超限回退只读原文，不能让页面失去响应。
- 现有 WalletStore `getRange` 会先读取完整对象再切片：本单仅保证 RPC 返回量和页面处理量有界，不把它描述成底层真正的分块磁盘读取。Worker 预览任务限制并发，快速切换不堆积大对象读取。

### 7.3 Markdown 行为

禁用内嵌 HTML、脚本、iframe 和自动加载远程资源。图片以占位说明显示，预览不能因打开文档而产生网络请求。链接过滤可执行及危险协议；允许的 HTTP(S) 链接只在用户主动点击时打开，外部窗口不保留 opener。相对链接在本期显示目标文本，不映射为任意存储读取或应用路由。

开工时先核对已有 UI 与依赖；如需增加 Markdown 渲染库，仅为本期渲染范围引入必要依赖，并验证 Worker/Web bundle 边界。

### 7.4 一致性与失效

选中文件才请求内容，以列表记录的版本作条件读取。文件变化返回版本冲突并提示“文件已更新，请重新加载”，不能静默展示另一个版本；不存在时显示“文件已不存在”。刷新后可获取最新版本。

快速切换采用取消加请求序号校验。每次请求与响应均校验当前选择及钱包/会话/Worker 世代；迟到响应不得覆盖新选择，也不得在锁定后重新显示内容。切换、锁定、重置和离开页面及时清除旧预览。

### 10.2 第一轮审查修复（2026-10-02）

首轮验收提出 5 项问题，均已在本单既定范围内落地，不新增需求。其中第 1 项（授权）与第 5 项（渲染有界）在第二轮复核中被指出仍有缺口，已分别由 §10.3 的第 1、4 项继续修复；下面第 1、5 条的描述只反映本轮状态。

1. **[P1] 根浏览授权不再依赖调用方自报身份（A01）。**
   `storage.browse.open` 的 wire 请求去掉了 `unitId`：身份字段无法伪造，也不再逐字比对任何字符串。Coordinator 改为在已验证的 peer 上下文里签发与端口绑定的专属授权（`issueStorageBrowseAuthorization`），要求该 peer 已完成 `session.open`、持有当前会话世代的 committed binding、钱包已解锁且未被撤销。浏览服务只按 `authorizationId` 查这张表（`trustedAuthorization`），并在每次调用时重新核对，因此授权被撤销、端口断开或世代推进都会让已发放的会话立即作废。核验排在装配浏览服务之前：未受信任的调用方连 WalletStore 都碰不到。页面代理与客户端不再传递任何单元 id。
2. **[P1] JSON 预览按需展开，深层内容不再崩溃（P01/P06）。**
   树化只预生成前 `JSON_DEFAULT_EXPAND_DEPTH` 层，再深的容器作为可展开节点存在，展开时由 `jsonChildrenOf` 一次只生成一层（调用深度恒为 1）；宽度按窗口生成，剩余成员由「显示更多成员」逐段生成，10,000 层 JSON 因此不再 RangeError。原文切换按钮已接通到预览面板，原文视图直接显示文件文本（不再 `JSON.stringify`，那既会改写内容也会在深文档上栈溢出），建树异常同样回退原文。
3. **[P2] 刷新不再把已更新或后续页文件误报为删除（L01/U01）。**
   节点身份改为「种类 + 完整路径」（`isSameNodeIdentity`），不再要求大小、时间与版本一致；同路径被改写后按新元数据重新预览。当第一页里找不到选中项时（可能是还没翻到那一页），页面改为直接读取该路径来核实，核实到内容就保留并采用返回的版本，只有确实读不到才清除并提示。
4. **[P2] 合法 JSON 标量与损坏 JSON 可见（P01/P02）。**
   `parseJsonText` 按完整 JSON 语法解析，声明为 JSON 的文件接受 `123`/`true`/`null`/`"hello"`；解析失败且 UTF-8 有效时一律 `json-broken`（原文 + 失败提示），不再因「不以 `{` 或 `[` 开头」改判二进制。无声明、无扩展名时仍只认对象/数组，避免把普通文本里的标量误当 JSON。
5. **[P2] 目录列表与文件树的有界渲染（P06/F03）。**（可达性已解决，有界性由 §10.3 第 4 项收口）
   固定 `slice(0, 400)` 被展示窗口取代：列表与树的每个目录各渲染一个 200 行的窗口并给出「显示更多」。第二轮复核指出「显示更多」不断扩大同一个从零开始的切片，连续展开后仍会一次性渲染全部行，因此改为固定大小的展示分页（§10.3 第 4 项）。

顺带修正：浏览页的插值占位符原本写成单花括号（`{shown}`），而本仓库的 i18next 实际使用双花括号，导致截断提示、JSON 计数等文案在真实运行时原样显示占位符。已统一为 `{{…}}`（与 `plugin-background` 一致）。

### 10.3 第二轮复核修复与浏览器验收（2026-10-02）

第二轮复核指出 4 类代码问题，并要求补齐浏览器验收。全部在本单既定范围内落地。

1. **[P1] 撤销之后才到达的读取不再返回内容（阶段 B / L02）。**
   读取前的会话检查挡不住「读取期间被撤销」：底层 WalletStore 可能忽略 AbortSignal，在撤销之后才成功返回。现在有三重栅栏——并发闸**入场**复核（`ReadGate.run(task, admit)`，排队期间被放弃的请求根本不会开始读）、`await` 之后**再次**核对会话与授权（`assertSessionLive`，`list` 与 `preview` 都做）、返回前检查取消状态。读取期间的撤销/取消统一翻译成 `storage_unavailable`（`normalizeRevoked`），让页面知道「句柄没了」而不是把 IndexedDB 的原始错误显示成内容读取失败。
   同时修正了授权门本身的一个过严条件：不能要求 binding 的 `sessionEpoch` 等于当前世代——应用在锁定态启动，`session.open` 发生在解锁之前，而解锁会换一代 epoch。世代一致性由授权记录的三个世代承担（每次调用都核对），这条过严条件会让真实页面在解锁后被自己的门挡住（真实浏览器 Gate 曾因此报 “This request is not permitted.”）。它也是 Connect/第三方被拒绝的真正原因：这些主体没有 Coordinator peer 上下文，走不到签发这一步。
2. **[P2] JSON 预览不再失真，原文切换双向可用（P01）。**
   空容器与标量分开：`{}` 与 `[]` 走容器分支（如实显示 `object · 0` / `array · 0`），不再被标量视图显示成 `null`。原文切换按钮移出分支，成为树视图与原文视图共用的工具栏，切到原文之后仍能切回树。视图开关（原文 / Markdown 源码 / K-V 原始信封）按文件生效：换文件回到默认视图，自动换行仍是跨文件的用户偏好。
3. **[P2] 刷新核验不再把读取失败当作删除（L01/U01）。**
   只有 `storage_not_found` 触发「文件已不存在」并清除选择；`storage_provider_error`、`storage_forbidden` 等都不证明文件被删，改为保留选中项、显示可重试的失败状态（预览错误态新增「重试」）。真正的取消（`AbortError` / `transport-error`）静默退出；`storage_unavailable`（锁定、句柄作废、Worker 重启）给出明确的「暂不可用」说明，不再被静默吞掉。
4. **[P2] 渲染量真正有界（P06/F03）。**
   `browseDisplayWindow`（不断放大的切片）被 `browseDisplayPage` 取代：固定 200 行一页，翻页只换下标窗口，越界页夹回最后一页。列表与文件树的每个目录都用它，因此任一时刻渲染的行数与目录规模无关，而每个已加载子项都能翻到。存储分页（继续加载）与展示分页互不依赖。

**浏览器验收已执行**（`e2e/integration/gates/local/storage-browse-page.spec.ts`，真实 Chromium、生产 preview、真实 SharedWorker 与 IndexedDB，5 个场景全部通过）：
