# 001：首次初始化恢复 AWS、R2 与普通 S3 配置方式

> 日期：2026-09-09
>
> 状态：待实施
>
> 优先级：P0
>
> 需求来源：首次初始化页面选择 S3 后，桶参数不能只提供一套通用表单；必须恢复 AWS S3、Cloudflare R2、普通 S3-compatible 三种配置方式。
>
> 本单只定义修改范围和验收标准，不代表代码已经实施。

## 1. 问题与目标

当前首次初始化流程只有两种桶后端：`Local` 和 `S3`。这个后端划分是正确的，但 `S3` 的“桶参数”步骤只显示一套通用字段，用户必须自行填写 `Endpoint`、`Region` 和请求风格，丢失了旧版已有的三种配置方式：

1. AWS S3；
2. Cloudflare R2；
3. 普通 S3-compatible。

本次修改恢复的是 **S3 配置模板**，不是增加三种存储后端。底层仍只有 `local` 与 `s3`，三种 S3 配置最终统一转换成 KeymasterHold 当前支持的通用 S3 连接配置。

目标流程：

```text
选择桶类型
  ├─ Local → 填写 Local 参数
  └─ S3 → 选择 S3 配置方式
             ├─ AWS S3
             ├─ Cloudflare R2
             └─ 普通 S3-compatible
          → 填写对应参数
          → 测试连接
          → 设置桶密码
          → 创建或导入第一把 Key
          → 确认并初始化
```

## 2. 固定需求

### 2.1 页面层级

- 首个步骤继续只显示 `Local` 和 `S3`，不把 AWS、R2 错当成与 S3 平级的后端。
- 用户选择 `S3` 后，在“填写桶参数”步骤顶部显示“配置方式”。
- 配置方式固定为：`AWS S3`、`Cloudflare R2`、`普通 S3-compatible`。
- 默认选中 `AWS S3`，与旧配置页默认值一致。
- 切换配置方式时，清空上一种方式专有的目标字段和全部访问凭据，防止把 R2 凭据误提交到 AWS；桶显示名称可以保留。
- 配置方式、字段名称、校验错误和说明均提供中文含义，不能要求用户根据英文参数名猜测用途。

### 2.2 三种方式的字段

| 配置方式 | 用户填写字段 | 自动处理字段 |
|---|---|---|
| AWS S3 | `Region`（AWS 区域）、`Bucket`（物理桶名称）、`Access Key ID`（访问身份）、`Secret Access Key`（访问密钥）；可选 `Session Token`（临时会话令牌）、`Prefix`（对象前缀） | 按 AWS 区域生成标准 HTTPS Endpoint；`forcePathStyle=false` |
| Cloudflare R2 | `Account ID`（Cloudflare 账户 ID）、`Endpoint Variant`（端点类型：Default / EU / FedRAMP）、`Bucket`、`Access Key ID`、`Secret Access Key`；可选 `Prefix` | 生成 `https://<accountId>[.<variant>].r2.cloudflarestorage.com`；`region=auto`；`forcePathStyle=false` |
| 普通 S3-compatible | `Endpoint`（HTTPS 服务地址）、`Region`（签名区域）、`Bucket`、`Access Key ID`、`Secret Access Key`；可选 `Session Token`、`Prefix`、`Force Path Style`（强制路径风格请求） | 不猜测厂商，不改写用户填写的服务目标，仅做规范化和安全校验 |

补充约束：

- AWS Endpoint 生成必须覆盖代码明确支持的 AWS 分区；不能只拼接一个对所有区域都声称有效的字符串。若本次只支持标准商业分区，页面和校验错误必须明确说明，不得静默生成错误地址。
- R2 `Account ID` 必须为 32 位十六进制字符串；`Endpoint Variant` 只允许 `default`、`eu`、`fedramp`。
- 普通 S3 Endpoint 必须是无用户名、无密码、无 query、无 fragment 的绝对 HTTPS URL。
- 三种方式都继续要求 `probe.ok === true` 且 `conditionalWrites === "native"`，不能因为是 AWS 或 R2 模板而跳过原子条件写能力验证。
- 测试产生的临时对象必须继续限定在候选逻辑桶根下，并在成功或失败后清理。

### 2.3 统一连接格式

新增页面草稿字段建议如下；字段名可按现有代码命名调整，但不得创建第二套含义相同的持久化模型：

| 字段 | 中文含义 | 持久化规则 |
|---|---|---|
| `s3ConfigMode` | S3 表单配置方式：AWS、R2 或普通 S3 | 页面输入语义；不作为新的桶后端 |
| `accountId` | Cloudflare 账户 ID | 仅用于生成 R2 Endpoint |
| `endpointVariant` | R2 端点类型 | 仅用于生成 R2 Endpoint |
| `endpoint` | 最终 S3 HTTPS 服务地址 | 作为通用 S3 配置加密保存 |
| `region` | AWS 区域或 S3 签名区域 | 作为通用 S3 配置加密保存 |
| `bucket` | 物理对象存储桶名称 | 作为通用 S3 配置加密保存 |
| `accessKeyId` | 访问身份 | 只进入本次页面内存和桶级加密配置 |
| `secretAccessKey` | 访问密钥 | 只进入本次页面内存和桶级加密配置 |
| `sessionToken` | 临时凭据的会话令牌 | 可选；只进入通用 S3 加密配置 |
| `prefix` | 用户指定的对象路径前缀 | 可选；Provider 仍须追加 Keymaster 逻辑桶隔离根 |
| `forcePathStyle` | 是否使用路径风格请求 | 仅普通 S3 允许用户设置 |

提交给 `InitialSetupPlan.connection` 前必须统一转换为现有 `S3BucketConnectionConfigV1`：

```text
AWS 表单 ─┐
R2 表单  ─┼─ normalize/convert ─→ S3BucketConnectionConfigV1 ─→ InitialSetupPlan
普通 S3 ──┘
```

- `InitialSetupPlan.backend` 仍为 `s3`。
- KeymasterHold 的 `StorageConfig` 仍为 `kind: "s3"` 的标准结构；不得向严格 Hold 文档私自加入 UI 专用字段。
- 不新增 AWS Provider、R2 Provider 或三套读写实现；`createS3BucketProvider` 仍是唯一 S3 桶 Provider 入口。
- 配置方式可以作为当前页面的显示状态；如果产品要求编辑桶时精确保留原配置方式，应另行定义版本化、非秘密的显示元数据。禁止依靠 Endpoint 模糊猜测后冒充可靠持久化结果。

## 4. 自动化验收

至少增加下列测试：

| 编号 | 场景 | 通过标准 |
|---|---|---|
| A01 | 选择 S3 进入桶参数 | 可见 AWS、R2、普通 S3 三种方式，默认 AWS |
| A02 | AWS 完整填写 | 生成正确通用 Endpoint/Region/Bucket，测试通过后进入密码步骤 |
| A03 | AWS 缺少 Region 或凭据 | 页面显示对应中文必填错误，不调用 Provider probe |

| A06 | 普通 S3 | 原样保留规范化后的 HTTPS Endpoint、Region、Prefix 和 path-style 选择 |
| A07 | 普通 S3 非 HTTPS或携带 URL 凭据 | 校验拒绝，不发送秘密到诊断信息 |
| A08 | 配置方式切换 | 专有字段、Access Key、Secret 和 Session Token 被清空，测试状态失效 |

| A12 | Hold 往返 | 三种方式转换后的连接经加密、解密、导出、导入后仍可创建同一物理 Provider |
