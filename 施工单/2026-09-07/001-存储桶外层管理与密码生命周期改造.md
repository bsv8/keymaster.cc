## 1. 目标

交付可独立于 Key 系统进入的多桶管理层，支持 S3 与 Local（localStorage），按“桶 → Keys”选择身份。桶配置及 Key 使用同一个桶密码；每次解密新 Key 都重新输入密码，操作结束清理密码与派生上下文，只保留当前桶凭据和当前 Key 私钥。

已保存的桶不再做启动或运行期探测；实际读写错误就地显示，业务保存可重复重试。

全配置导入/导出统一使用 KeymasterHold SDK。冷导出无需密码、解密或重新加密；写入时保存同一公共 KDF 参数下的记录与完整文档认证快照，导出时仅组合并序列化。

本次文档交付不代表已完成程序实施。以下复选项全部须以代码和验证证据关闭。

## 6. 冷导出实施注意事项

KeymasterHold 当前 `sealDocument(parts, context)` 会逐条解密校验并计算整文档 HMAC；它必须发生在受认证配置修改的临时密码操作内，不能放进导出按钮处理函数。`serializeDocument` 不需要密码，但也不会补算或修复认证标签。

实施证据必须包含密码清理后直接导出的 API 调用轨迹，以及随后使用原密码验证导出文件成功的测试。仅证明 JSON 可以下载不算完成冷导出。

新/旧配置与 Keys 的跨存储发布、导出快照的读取保护和旧版本清理必须统一设计；不能为导出而持久化密码派生的 HMAC 密钥，也不能为简化组合而把全部 S3 Keys 放进本机目录。
