# 002：全局余额广播

> 日期：2026-09-21
>
> 状态：设计定稿，未实施
>
> 优先级：P1
>
> 上游约束：[P2PKH](../../docs/P2PKH.md) 的「余额是 UTXO 快照派生、未知不是 0」；
> [001 转账单](./001-transfer-收款方合并与P2PKH范围收敛.md) 的 testnet 开关规则

## 1. 背景与问题

当前余额链路是「快照 → 失效广播 → 各消费点各自重算」，缺少统一的带值广播：

1. **消费点分散**，每个点都自己处理 `includeTestnet` 与「未知 vs 0」：
   - `p2pkh.balance` resource（`packages/plugin-p2pkh/src/manifest.ts:705`）——目前只有孤儿组件
     `P2pkhBalanceWidget` 消费，未挂首页；测试却引用它（`P2pkhBalanceWidget.test.tsx`）。
   - `p2pkh.wallet.balances`——钱包页（`P2pkhWalletPage.tsx:257-263`）。
   - `P2pkhAssetProvider.toSummary()`——资产总览 `assets.holdings`
     （`p2pkhAssetProvider.ts:100-119`、`apps/web/src/system/assets.tsx:199`）。
   - `P2pkhTransferProvider.toOffer()`——`/transfer` offer 余额
     （`p2pkhTransferProvider.ts:89-112`）。
   - 以上全部直接调 `p2pkhService.getAssetBalance()`（`p2pkhService.ts:531-539`）。
2. **现有跨 tab 广播不携带值**：`AssetDataInvalidationEvent` 契约明确「payload 不携带金额」
   （`packages/contracts/src/assets.ts:123-137`）。非 resource 消费者拿不到余额，只能自己 RPC 重拉；
   新增显示点必须复制一遍 map / testnet / 未知逻辑。
3. **跨 tab 设置滞后**：`handleP2pkhSettingsUpdate` 成功后只发 `background.snapshot`
   （`keymasterSessionCoordinator.worker.ts:11489-11503`），而窗口 client 对
   `background.snapshot.changed` 只更新 `taskSnapshots`，不更新 `p2pkhSettings` 缓存
   （`apps/web/src/keymasterSessionCoordinatorClient.ts:1721-1723`）。另一 tab 关闭 testnet 后，
   本 tab 仍按旧设置显示 testnet 余额。

现有可复用的基础设施已经完整：Worker 单点刷新 + `asset.data-changed`（含 revision/合并/重放）、
`AssetDataNotifier` 微任务合并、`p2pkhService.onDataChanged`、Resource Store 失效重拉。
本单只缺「带值的统一余额快照」。

## 2. 目标

1. 新增全局余额广播：唯一的 `GlobalBalanceSnapshot`，余额 map 按 `includeTestnet` 决定是否含
   testnet 键。
2. 所有余额显示与转账 offer 统一消费广播；新增消费点不再重复实现 testnet / 未知语义。
3. 同步结果（Worker 快照刷新、转账提交、设置切换、active key 变化）驱动广播，所有视图自动跟随。
4. 不改数据真值：广播始终是 Worker UTXO 快照的只读投影。

## 3. 冻结的不变量

### 3.1 真值与语义

- [ ] 广播是快照的**只读投影**，不落盘、不持久化，不成为第二个余额真值。
- [ ] `includeTestnet=false`：map 中**不得出现 testnet 键**（不是 0）。
- [ ] `includeTestnet=true` 且快照不可用：testnet 键必须存在且 `available=false`（未知 ≠ 0）。
- [ ] `available=false` 一路传播，任何消费方不得渲染成 0。
- [ ] 广播 payload 的 `publicKeyHex` 与消费方当前 active key 不一致时丢弃。
- [ ] 锁屏 / 切换 owner / 无 active key：广播为空快照，不得残留上一个 key 的余额。
- [ ] 签名真值不变：转账 prepare/submit 前仍强制 `p2pkhUtxosRefresh`（`p2pkhService.ts:246-252`）；
      广播只用于显示。
- [ ] 广播更新**不得**产生 WoC 网络请求；网络请求只发生在 Worker 的单点刷新任务里。
- [ ] 余额内容无变化时不递增 revision、不发通知，避免无意义重渲染。

### 3.2 传输与合并

- [ ] 复用 `asset.data-changed` topic，不新增 Coordinator topic。
- [ ] `kinds` 白名单新增 `"balance"`；Worker 快照刷新与转账提交事件必须携带该 kind。
- [ ] 同一 provider+owner 的连续失效事件由 `AssetDataNotifier` 合并（既有语义），广播只在合并后重算一次。
- [ ] 广播值在同一 tab 通过 capability + `messageBus` 双通道可见；跨 tab 由 topic 保证最终一致。

### 3.3 转账页金额参考

- [ ] `/transfer` 金额输入旁显示**当前收款网络的可用余额参考值**（单位 sats），供用户填写金额时参考。
- [ ] 参考网络必须跟随收款方网络（001 规则）：地址模式由地址 version 反推并锁定；公钥模式随用户选择；
      不允许参考值与实际签名的网络不一致。
- [ ] 参考值取自全局余额广播对应键（`mainnet` / `testnet`），不是页面自己 RPC 拉的独立口径。
- [ ] 快照不可用时显示「未知」，不得显示 0；`includeTestnet=false` 时不显示 testnet 参考。
- [ ] 余额广播刷新只更新参考文案，**不得覆盖、重置或改写用户已输入的金额**。
- [ ] 「全部」按钮语义不变（发送全部并扣除矿工费）；余额参考不替代输入校验。

## 4. 数据模型（contracts）

新增 `packages/contracts/src/balance.ts`，余额消息类型由 plugin-p2pkh **提供实现**（与 001 中
`P2pkhAddressCodec` 的做法一致）。

`P2pkhBalance` / `P2pkhBalanceBreakdown` 从 `plugin-p2pkh/p2pkhContracts.ts` 上移到 contracts，
plugin-p2pkh 原路径重导出以兼容现有 import。理由：广播契约不能依赖业务插件。

```ts
import type { BsvNetwork } from "./vault.js";
import type { P2pkhBalance } from "./balanceTypes.js";

/** 余额广播网络键：固定 mainnet/testnet，与 UI 文案一致（已定）。 */
export type BalanceNetworkKey = "mainnet" | "testnet";

/** 内部网络 → 广播键的唯一映射：main→mainnet，test→testnet。 */
export const BALANCE_NETWORK_KEYS: Record<BsvNetwork, BalanceNetworkKey> = {
  main: "mainnet",
  test: "testnet"
};

/** 全局余额快照（跨显示/转账消费的唯一形态）。 */
export interface GlobalBalanceSnapshot {
  /** 快照归属 owner：压缩公钥 hex（小写）；空串表示无 active key（锁屏/未选择）。 */
  publicKeyHex: string;
  /** 快照生成时的 testnet 开关；消费方以此为准，避免跨 tab 设置滞后。 */
  includeTestnet: boolean;
  /** 网络余额表：mainnet=主网，testnet=测试网；testnet 键仅在 includeTestnet=true 时出现。 */
  balances: Partial<Record<BalanceNetworkKey, P2pkhBalance>>;
  /** 广播版本：本 tab 内严格递增，仅内容变化时 +1；用于去重与丢弃乱序。 */
  revision: number;
}

/** 余额广播服务（窗口内单例 capability）。 */
export interface BalanceBroadcaster {
  /** 读取最新快照（同步，不出网）。 */
  getSnapshot(): GlobalBalanceSnapshot;
  /** 订阅快照变更；返回取消订阅。 */
  subscribe(handler: (snapshot: GlobalBalanceSnapshot) => void): () => void;
}

/** 无 active key / 锁屏时的空快照。 */
export function emptyGlobalBalanceSnapshot(): GlobalBalanceSnapshot;

export const BALANCE_BROADCAST_CAPABILITY = defineCapability<BalanceBroadcaster>({
  kind: "local",
  id: "balance.broadcast",
  version: "1",
});
```

金额字段沿用现有 `P2pkhBalance`：

```ts
export interface P2pkhBalance {
  /** 可花费余额（sat）。available=false 时无意义。 */
  total: number;
  /** 快照是否可信；false 表示未知，禁止显示 0。 */
  available?: boolean;
  /** 明细：confirmed / unconfirmed / spendable / pendingInputClaims。 */
  breakdown?: P2pkhBalanceBreakdown;
}
```

**为什么 map 的值不是裸 sat 数字**：`available`（未知语义）和 `breakdown`（钱包页明细）
必须一起传递，否则消费方无法区分「0」与「未知」。

## 5. 广播分层与数据流

```text
Worker（余额真值持有者）
  UTXO 快照刷新成功 / 转账提交成功 / 设置更新 / 锁屏或切 owner
    └─ publishTopicEvent("asset.data-changed", { providerId:"p2pkh", publicKeyHex, kinds:[...,"balance"] })
         │  （topic stream 跨 tab / 跨 worker，revision 去重与重放由 client 负责）
         ▼
Window 装配层 bootstrapPlugins（apps/web/src/bootstrapPlugins.ts:748-755）
    coordinatorClient.subscribeTopic("asset.data-changed") → dataNotifier.emit(event)
         ▼
plugin-p2pkh p2pkhService
    ├─ 重算启用网络余额（只读 coordinator 内存快照，不出网）
    ├─ 更新 BalanceBroadcaster 快照；内容变化才 revision+1
    ├─ messageBus.publish(P2PKH_MSG.BALANCE_CHANGED, snapshot)   ← 同 tab / 非 React 消费者
    └─ 通知 onDataChanged 现有订阅者（asset provider / transfer offer / 资源失效）
         ▼
Resource Store
    p2pkh.balance（统一资源）→ useResourceSelector / useOptionalResourceSelector → 页面
```

### 5.1 关键取舍：不新增 Coordinator topic

`asset.data-changed` 已有跨 tab revision、微任务合并、baseline 重放、parser 校验；
新增 topic 要同步改 4 处契约（`CoordinatorTopic`、parser、worker 发布、窗口订阅），收益低。
因此新增 kind `"balance"`（`assets.ts` kinds 联合 + `sessionCoordinatorRuntime.ts:3193-3196`
白名单），复用现有通道。

### 5.2 关键取舍：窗口侧重算余额，Worker 只发失效

- 余额 `spendable` 依赖本地 input claims、`protectedOutpoints`、签名过滤，
  这些逻辑已在窗口 `plugin-p2pkh` 单点实现（`calculateP2pkhBalanceBreakdown`）。
- 若把重算搬到 Worker，会形成第二套实现，且 `protectedOutpoints` 注册表在窗口侧，
  容易出现「显示可花 > 实际可签」的危险偏差。
- 每个 tab 各重算一次可以接受：读取的是 Coordinator 内存快照（RPC），
  启用网络数 ≤ 2，**不产生 WoC 请求**。
- 若未来需要「窗口关闭也能广播」或全局统一 revision，再评估 Worker 权威计算。

### 5.3 跨 tab 设置修复

`BackgroundSnapshotEvent` 增加可选字段：

```ts
export interface BackgroundSnapshotEvent {
  // ...现有字段
  /** P2PKH 网络范围配置的最新值；设置变更后必须携带。 */
  p2pkhSettings?: { includeTestnet: boolean };
}
```

- Worker `handleP2pkhSettingsUpdate`（`keymasterSessionCoordinator.worker.ts:11489-11503`）
  发布 `background.snapshot` 时携带 `p2pkhSettings`。
- client `applyTopicEvent` 同时更新 `bootstrapSnapshotCache.p2pkhSettings`（当前只更新 taskSnapshots）。
- `p2pkhService` 订阅 `background.snapshot` topic：更新 `cachedSettings` → 触发重算广播。
- 顺带修复 `p2pkh.settings` resource 跨 tab 不刷新的既有缺口（可选：resource 也订阅该 topic）。

## 7. 消费侧与资源

### 7.1 统一资源

改造现有 `p2pkh.balance` resource（`manifest.ts:705-731`），不再自己 RPC 组装，而是读广播快照：

```ts
resources.register<GlobalBalanceSnapshot, readonly string[]>({
  id: "p2pkh.balance",
  scope: "active-key",
  key: (_args, context) => ["p2pkh.balance", context.activePublicKeyHex ?? "none"],
  load: async () => broadcaster.getSnapshot(),
  subscribe: (_args, _ctx, invalidate) => broadcaster.subscribe(invalidate),
  equals: (prev, next) => !prev || !next
    ? prev === next
    : prev.revision === next.revision && prev.publicKeyHex === next.publicKeyHex,
  invalidation: "microtask"
});
```

- 值类型由 `{ bsv, bsvtest }` 改为 `GlobalBalanceSnapshot`（map）。
- 不再需要 `getAssetBalance` 作为显示真值；`service.getAssetBalance` 保留给不消费广播的旧调用，
  内部改为读广播快照（同一入口，避免两套口径）。

### 7.2 消费点迁移

| 消费点 | 现状 | 迁移后 |
| --- | --- | --- |
| `P2pkhBalanceWidget` | 读 `p2pkh.balance` 的 `{bsv,bsvtest}` | 读 map；`home.register` 挂首页（已定；manifest 已声明 `HOME_REGISTRY_CAPABILITY` 依赖） |
| `P2pkhWalletPage` | `p2pkh.wallet.balances[network]` | 改读 `p2pkh.balance`；`p2pkh.wallet` 移除 `balances` 字段，消除双路径 |
| `P2pkhAssetProvider.toSummary` | `await service.getAssetBalance(assetId)` | 广播快照对应网络；缺失/未知按 `available:false` 输出 |
| `P2pkhTransferProvider.toOffer` | `await service.getAssetBalance(assetId)` | 同上；offer 展示随广播刷新 |
| `P2pkhTransferWidget` 金额输入 | 无余额提示 | **新增**：金额输入旁显示当前网络可用余额参考（见 7.4）；数据来自 `p2pkh.balance` 广播快照 |
| `/transfer` 页面 | 展示 offer.balance | 页面本身不改；金额旁参考由 provider widget 负责（未来其他 provider 复用同一广播 capability） |
| 未来新显示点 | 各自拼装 | 只用 `p2pkh.balance` resource 或 capability |

### 7.3 可选 hook

`useGlobalBalances()`（runtime/react 或 contracts 侧）：
`useOptionalCapability(BALANCE_BROADCAST_CAPABILITY)` + `useSyncExternalStore`，
在插件被禁用（capability 缺失）时降级返回空快照，不抛错。
Resource 存在时优先用 resource；hook 服务于不方便用 resource 的宿主代码。

### 7.4 转账金额旁的余额参考

位置：`P2pkhTransferWidget` 的金额输入行（`p2pkh-transfer-widget__amount-row`，
`P2pkhTransferWidget.tsx:259-272`），在「金额 (sats)」输入框旁展示参考值。

```text
金额 (sats)  [ 输入框 ]  [全部]      可用余额：12,345 sats（主网）
```

规则：

- 数据来源：插件内 `p2pkh.balance` resource → `GlobalBalanceSnapshot`；
  `network = assetIdToNetwork(assetId)` → 广播键 `mainnet` / `testnet`。
- 网络切换（001 的收款方网络）：地址模式锁定地址网络；公钥模式用户切换后，
  offer / `assetId` 随之变化，参考值自动切到对应网络，无需额外订阅。
- `includeTestnet=false`：testnet offer 不会出现，因此不存在 testnet 参考。
- `available === false` 或键缺失：显示「可用余额未知」；**绝不显示 0**。
- 刷新不打断输入：广播更新只替换参考文案，`form.amount` 保持不变；
  输入框不因余额变化被清空、重置或自动回填。
- 「全部」语义不变：仍由 `P2pkhTransferWidget` 现有 send-all 逻辑处理，
  参考值不参与签名真值；prepare/submit 仍强制刷新快照（3.1）。
- 超额输入只做展示层提示（可选）：若实施时增加「超过可用余额」内联提醒，
  必须是非阻断提示，最终拦截仍由 prepare 阶段的既有校验负责。

## 8. 命名与单位

- **map 键**固定 `mainnet` / `testnet`（已定，与 UI 文案一致）。代码内部网络仍是 `BsvNetwork`
  （`main` / `test`，`packages/contracts/src/vault.ts:25`），只在广播边界用
  `BALANCE_NETWORK_KEYS` 做一次映射；禁止在其它位置散落 `mainnet` / `testnet` 字符串。
- 资产映射沿用 `assetIdToNetwork`：`main→bsv`、`test→bsvtest`。
- 金额单位 sat（整数 number）。BSV 总量上限 21e14 sat < `Number.MAX_SAFE_INTEGER` (9.007e15)，
  精度安全；未来 token bigint 不在本单范围。

| T08 | 失效事件乱序或旧 revision | 被丢弃，不覆盖新值 |
| T09 | 转账签名路径 | 仍强制刷新快照，不使用广播旧值 |
| T10 | capability 缺失（插件禁用） | 消费方降级为空快照/未知，不崩溃 |
| T11 | 快照刷新失败 | 保留旧快照/未知，不把 0 写回广播 |
| T12 | `/transfer` 金额输入旁（主网收款方） | 显示 mainnet 可用余额参考，单位 sats |
| T13 | 收款方网络切到 testnet（includeTestnet=true） | 参考值切换为 testnet 余额，不残留主网数值 |
| T14 | 快照未知 / includeTestnet=false | 显示「可用余额未知」；不出现 testnet 参考 |
| T15 | 余额广播刷新时用户已输入金额 | 输入框内容不变，只有参考文案更新 |

## 13. 开放风险

1. **map 键的第二套命名**（已定 `mainnet` / `testnet`）：与内部 `BsvNetwork`（`main` / `test`）
   不同，必须通过 `BALANCE_NETWORK_KEYS` 单点映射，评审时检查是否有散落字符串。
2. **revision 作用域**：本设计为 tab 内单调，不保证跨 tab 可比。若未来需要跨 tab 排序，
   需由 Worker 提供全局 revision（届时可能改为 Worker 权威计算）。
3. **`P2pkhBalance` 上移 contracts** 会触碰 `plugin-p2pkh` 的公开 import；用重导出兼容，
   但要确认 `lint:boundaries` / contracts 门禁通过。
4. **`p2pkh.wallet` 移除 `balances`** 会影响现有测试与 e2e 消费；迁移期间需一次性切换，
   不允许双路径长期共存。
5. **首页挂载**（已定）：`P2pkhBalanceWidget` 注册为 home widget 时需确认 `slot` 与 `order`
   不与 `assets.overview`、`bsv-price.snapshot` 冲突。
