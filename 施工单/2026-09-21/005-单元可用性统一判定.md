## 2. 迁移路径

与设计同批交付，**不留中间态**。

1. **契约先行**：`state` 二值化、新增原因类型、快照加 `reasons`；卖方状态新增「等待依赖」
   一档取值。
2. **目录合并**：依赖字段合并为一份，含 `msfile` 对 `sat-subscription` 的单元依赖补录
   （即事故现场那条隐式依赖）；补依赖图无环与未知 id 校验。
3. **统一判定**：可用性判定落为唯一实现，框架门与本地判定合并到它。
4. **进程内订阅**：可用性订阅上线，替换单钩子写法。
5. **删兜底**：四个 `ensure*` 的 reconcile-and-pray 全部删除，37 个调用点收敛。
6. **卖方改造**：按设计稿第 7 节落地，永久错误状态不再表达「依赖还没好」。
7. **删逃生口**：门外测试逃生口及其分支移除，测试改用既有公开测试钩子。

顺序上 1–4 为新增、5–7 为删除。**第 5 步之后不得再有 reconcile-and-pray 残留**，这是本单
验收硬点。

## 4. 自动化验证矩阵

| 用例 | 断言 |
| --- | --- |
| 插件开 + 单元就绪 | `state === "ready"`，`reasons` 为空 |
| 插件开 + 单元未就绪 | `state === "failed"`，含 `dependency-not-ready` 及对应 `dependencyId` |
| 插件关 | `state === "failed"`，含 `plugin-disabled` |
| 多依赖部分不满足 | `reasons` 逐条列出**全部**不满足项，不是只报第一个 |
| 无单元的产品 | 恒可用（`reasons` 为空） |
| 无依赖的单元 | 恒可用（`reasons` 为空） |
| 依赖图有环 | 启动期静态校验抛错，不进入运行 |
| 未知依赖 id | 启动期静态校验抛错 |
| 卖方：依赖预热中开开关 | 状态为「等待依赖」类，**不**永久错误、**不**拆索引 |
| 卖方：依赖随后就绪 | 经回调自动转就绪，**无需再切一次开关** |
| 卖方：开关关闭 | 短路，不评估可用性，不残留索引与运行时 |
| 回调语义 | `ready` 与 `failed` 双向都触发；重复同态为幂等重判 |
| 原因文案 | `text.fallback` 为英文；`text.key` 在 i18n 资源中可解析 |
| 禁止轮询 | 可用性路径无定时器、轮询或固定休眠重试 |
| 单一路径 | 无 reconcile-and-pray 残留、无门外逃生口 |

事故回归必须补一条：依赖预热未完成时开启卖方，覆盖「自动收敛且无需用户重切」。

## 6. 开放风险

1. **门内部状态无契约对应**：框架内部有 `blocked` 状态，契约快照没有对应字段。翻译规则若
   不集中，框架升级后会错位。缓解：翻译集中在唯一判定实现内，不散落。
2. **就绪语义变重**：合并后「就绪」同时意味着插件开、依赖满足、已启动。旧代码若只把它当
   「启动完成」用，会漏掉前两个条件。缓解：逐个复核 37 个调用点。
3. **删兜底会暴露既有隐性依赖**：某些调用点可能正依赖 reconcile 副作用才能工作，删除后
   测试转红。**这是本单要暴露的东西**：应把缺失依赖补进声明字段，**不得**恢复兜底。
4. **回调重入**：可用性抖动带来连续重判。缓解：重判必须幂等，世代令牌继续负责作废处理。
