# Keymaster

Keymaster 是本地优先的 BSV 浏览器钱包。它提供钱包身份、签名、加密、资产、消息、文件及外部 App 授权能力。

钱包数据保存在当前浏览器、当前站点的本地 IndexedDB 中。同一浏览器配置和站点保存一把钱包 Key；首次使用可创建或导入，日常使用通过密码解锁。

## 使用

打开交付方提供的 Keymaster 地址，按初始化向导创建或导入钱包。已初始化的钱包启动后进入锁定状态，输入钱包密码解锁。

[钱包使用说明](docs/使用说明.md) · [安装与部署](docs/安装与部署.md)

## 项目结构

主应用入口位于根目录 `src/`，静态文件位于 `public/`，运行时与功能插件位于 `packages/`。根目录统一管理应用依赖、版本和开发构建命令。

边测和集成测试由同级 `BSV8_Engineering` 仓库维护，测试专用页面钩子、夹具和构建配置也位于该仓库。

## 自行部署

使用 Node.js 22 和 pnpm 11.5.1，在项目目录执行：

```bash
pnpm install --frozen-lockfile
pnpm build
```

应用静态产物位于 `dist/`。将它部署到支持单页应用路由的 HTTPS 站点，保留随产物提供的响应头和路由配置。完整步骤见[安装与部署](docs/安装与部署.md)。

### 仲裁服务缺省配置

产品在钱包解锁后按钱包记录的 BSV 网络配置固定仲裁服务：`main` 使用 `wss://arbitration.bsv8.com/`，`test` 使用 `wss://arbitration-test.bsv8.com/`。新建、导入和重新解锁已有私钥共用这一路径。WIF 的网络由导入解析识别，hex 私钥使用用户选择的网络。

MSFile 设置页显示不可修改、不可删除的服务身份和完整连接地址；卖方还可以增加接受的仲裁公钥。保存设置不能移除固定仲裁方。当前两环境共用公钥与 PeerID，连接地址必须按网络选择。

底层 MSFile service 默认没有仲裁服务；测试通过 `arbitrationServices` 显式注入本地服务运行时的公钥和地址，外置 E2E 构建关闭产品内置服务。卖方在线交付后超过付款等待时间（缺省 60 秒，可在设置中调整）会自动申请仲裁并提交结算交易。买方从 MSFile 设置页“仲裁与文件取回”手动取回已授权内容。锁定/退出后不补跑计时，重新登录只显示状态和操作按钮；失败操作由用户手动继续。节点接受交易与区块确认分开展示。取回成功不等于费用池已结算：链上花费尚未查明时保留专款保护，用户通过“检查结算状态”继续核验，已取回文件仍可使用。

当前依赖 `go-bitfs@0.3.3` 通过 `patches/` 和 pnpm lockfile 应用可复现补丁，支持历史交付证据的仲裁/补签、精确托管计费检查及买方本地付款状态的取回验收。请使用 `pnpm install --frozen-lockfile` 安装，不能绕过补丁直接使用未修正的同版本 npm 包。
